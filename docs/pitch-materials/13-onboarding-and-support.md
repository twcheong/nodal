# Onboarding & Support

One slide / one leave-behind page. Goal: remove the "we don't have time to learn another tool" objection with concrete, small time commitments.

## Onboarding — we build the first workflow with you

| Step | What happens | Your time |
|---|---|---|
| 1. Kickoff call | Install Twixy, connect Chrome, set up the team workspace, pick the pilot workflow | 60 min |
| 2. Build session | We turn your existing process into a working workflow together, run it on a real client | 90 min |
| 3. Team handoff | Your second user runs the shared workflow; we watch and fix friction | 30 min |

**Total structured onboarding: about 3 hours, spread over the first week.** No IT project, no integration work, no data migration — Twixy runs alongside your current tools.

> Honesty note (internal): in-product guided onboarding is **planned**; today onboarding is founder-led and hands-on — for a pilot customer that's a feature, not a gap. Don't present a self-serve onboarding flow as existing.

## Support during the pilot

- **Async support** by email/chat — response within one business day, usually much faster.
- **Weekly 30-min check-in** during the 4-week pilot.
- **Execution-log-based troubleshooting:** when a workflow fails, the log shows the exact step, error, and timestamp — send us the run and we diagnose from that, no screen-recording archaeology.
- Workflow adjustments (site changed its layout, new step needed) are handled with you in the check-ins.

## After the pilot

- Same async support channel continues for subscribers.
- New-workflow build help: bring us a repetitive process, we help you turn it into a workflow.
- Product updates ship continuously through the desktop app; planned items (starter template library, guided onboarding, roles & permissions, output approval) reach pilot customers first.

## The message on the slide

> "You're not buying software and a PDF manual. In week one, your team's first real workflow is already running — we build it with you."
