# Pilot Timeline — 4 Weeks, One Workflow

Designed for the segment's short, informal buying process: a team member feels the pain → founder watches the demo → team tests real workflows → founder decides on time saved, ease of use, and price.

## At a glance

```
Week 0        Week 1           Week 2–3            Week 4
Kickoff  →    Baseline +   →   Run, reuse,    →    Readout +
(1 hr)        first workflow   share               decision
```

## Week 0 — Kickoff (one 60-minute call)

- Pick **one** painful repetitive workflow (default: competitor research; alternatives: content research, campaign monitoring, report prep).
- Confirm the preparation checklist (doc 10) is done.
- Agree success metrics and targets in writing (doc 07).
- Install Twixy, connect Chrome, create the team workspace. *(We drive; ~30 min of this call.)*

## Week 1 — Baseline + build

- **Days 1–3:** team works the old way, logging time on the pilot task (template provided).
- **Days 3–5:** working session (~90 min) with us: turn the process into a Twixy workflow, run it on one real client, fix configuration.
- **Exit criteria:** one workflow runs end-to-end on a real client; baseline numbers recorded.

## Weeks 2–3 — Run, reuse, share

- Team runs the workflow for **every applicable client** (target: 5+ runs).
- A second team member (not the builder) reuses it for another client.
- Founder checks progress via the status dashboard instead of asking for updates.
- Light-touch support: async chat/email, one 30-min check-in per week.
- **Exit criteria:** ≥5 runs, ≥2 users, execution-log review done once with the founder.

## Week 4 — Readout & decision

- One-page before/after scorecard against Week 0 targets.
- 30-min founder meeting: results, what failed and why (from execution logs), pricing.
- Decision: subscribe / extend pilot with a second workflow / stop.
