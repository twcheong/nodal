# nodal — 로드맵

각 마일스톤은 **데모 가능한 것**으로 끝난다. 리팩터링만 하는 마일스톤은 없다.
총 예상 15~16주 (풀타임 1인, 순차 진행 기준). — M6(MCP 서버) 신설로 2주 증가 (2026-08-23).

**진행 규칙**: 마일스톤을 건너뛰지 않는다. 특히 M1은 UI도 GPU도 없이 CLI만으로 완성한다.

## M5 — 고급 실행 (2주)

> **순서가 바뀌었다 (2026-08-23).** nodal 이 MCP 서버가 되면서 이 마일스톤의
> 무게 중심이 옮겨졌다 (`design.md` §12, `decisions.md` 2026-08-23).
> **서브그래프는 저작 편의가 아니라 MCP 툴의 단위**이고, `IS_CHANGED` 는
> 최적화가 아니라 정확성 요구사항이다. 아래는 그 순서다 — 항목 자체는
> 늘지도 줄지도 않았다.

**① 프로덕트가 여기 선다** — 이 둘 없이는 MCP 표면을 만들 수 없다

- [x] 서브그래프 노드 (그룹 접기) — **툴의 단위** (`design.md` §12.2).
      `list_templates()` / `run_template(id, params)` 가 노출하는 것이 이것이다.
      **펼치는 방식은 로드 시 평탄화로 확정** (2026-08-23, `design.md` §12.7) —
      캐시가 내부 노드 단위로 걸려야 파라미터 하나 바꾼 재호출이 전체 재계산이
      되지 않는다
- [x] `IS_CHANGED` 훅 — **정확성 요구사항** (`design.md` §5.3).
      AI 클라이언트는 같은 워크플로를 파라미터만 바꿔 반복 호출하고,
      캐시 무효화 오판을 사람처럼 "재실행" 으로 넘기지 못한다

**② 그래프 표현력** — 템플릿 하나가 여러 경우를 담으려면 필요하다

- [x] `ExecutionBlocker` + Switch/Router 노드 (§1.1 ④)
- [x] 배치/리스트 처리 노드

**③ 최적화** — 있으면 좋지만 프로덕트를 막지 않는다

- [ ] Lazy 입력 + `check_lazy_status` (`design.md` §1.1 ⑤)
- [ ] 노드 확장(서브그래프 반환) + ephemeral 노드 부모 추적 (§5.2) —
      **강등 확정 (2026-08-23).** 열린 질문 6 이 "로드 시 평탄화" 로 결론났으므로
      서브그래프가 이것에 의존하지 않는다 (`design.md` §12.7)

**완료 기준**: ① 조건 분기 그래프에서 안 쓰는 브랜치가 실행되지 않음을 로그로 증명.
② 서브그래프 하나를 파라미터만 바꿔 두 번 실행했을 때, 바뀐 파라미터 아래만
재실행되고 **바뀐 값이 결과에 실제로 반영되는지**를 함께 증명 (§5.3 의 과소·과대
무효화 양방향).

**필수 테스트 T6**: [ ] lazy + 노드 확장 + 캐시가 동시에 걸리는 케이스 — **미충족**.
노드 확장은 봉인 상태이고 lazy 는 `check_lazy_status` 노드 API가 없어 아직 열리지
않았다. `design.md` §5.2의 확장 목표와 §1.1 ⑤의 lazy 목표를 함께 구현한 뒤에야 이
조합 테스트가 성립한다. 따라서 M5 ③은 미완료다.

> (계획 세션 문서, 2026-08-25). 매핑: MCP 서버 표면·Origin 검증·비동기 실행 =
> M6.1b(`ed3240a`) · 템플릿 카탈로그 = M6.0(`1e69a07`) · 파라미터 규약 =
> M6.0b·M6.1a(`5ad9832`) · 이미지 입력의 `asset:` 경로 = 의도적으로 미구현
> (아래 항목 자체가 그 상태를 말한다) · 템플릿 3종 = M6.2. 체크박스는 여전히
> 사람이 실측을 보고 켠다 — 이 메모는 코드가 어디 있는지를 말할 뿐이다.

- [ ] MCP 서버 표면 — 템플릿 하나당 툴 하나(`run_template_<id>`)를 카탈로그에서
      동적 생성한다. `list_templates()` 는 거부된 템플릿을 답한다 (`design.md`
      §12.2). 스키마·타입·에러는 서버가 이미 소유한 것을 그대로 말한다.
      브리지를 두지 않는다 (§12.1)
- [ ] **`Origin` 헤더 검증 — 필수.** MCP streamable HTTP 는 DNS rebinding
      대상이고 스펙이 요구한다. **`127.0.0.1` 바인딩은 이것을 막지 못한다** —
      사용자가 브라우저로 연 악성 페이지가 도메인을 `127.0.0.1` 로 해석시켜
      `/mcp` 를 부를 수 있다. G2 로 MCP 가 캔버스와 같은 프로세스에 있어 위험이
      평균보다 높다 (§12.9 · §10). 인증(OAuth 등)은 **MVP 밖**이지만 이것은
      안이다 — 열린 질문이 아니라 구현 항목이다
- [ ] 템플릿 카탈로그 — `~/.nodal/templates/*.nodal.json` 디렉토리 하나.
      **발견 메커니즘을 두 개 만들지 않는다** (§12.8). §8 확장은 M7 에서 같은
      레지스트리에 등록하는 공급자로 합류한다
- [ ] 비동기 실행 — `run_template_<id>` 는 `run_id` 를 즉시 반환하고
      `get_run` / `cancel_run` 으로 받는다 (§12.6). progress notification 은
      **추가로** 보내되 의존하지 않는다. 상태 전이표가 §12.6 에 있다
- [ ] 파라미터 규약 — **시드는 명시적 파라미터** (§12.3 · §9.4). 템플릿이 선언한
      파라미터만 받고, 실패하면 어느 파라미터인지 지목한다. 결과는 에셋 참조로
      돌려준다 (§4.5)
- [ ] 이미지 입력의 `asset:` 경로 — 형식은 계약에 있고 **동작하지 않는다**
      (§12.3 의 현재/목표). 클라이언트가 이미지를 올리는 수단과 에셋 해시로 읽는
      노드가 있어야 닫힌다. 그때까지 `Image` 값은 파일 경로뿐이다
- [ ] 템플릿 3 종 — 제품 광고 수준의 실제 워크플로. **전용 코드 경로 없이**
      서브그래프로만 만들어진다는 것을 이것으로 증명한다

**완료 기준**: 외부 AI 클라이언트가 nodal 에 붙어 "이 제품 사진으로 인스타그램용
광고 이미지" 를 만든다. 같은 요청을 시드 고정으로 다시 하면 **같은 그림**이 나오고,
파라미터 하나만 바꾸면 **바뀐 노드 하류만** 재실행된다.

**의도적으로 뺀 것**: 저수준 `execute_graph` (§12.2) · 실시간 UI 가시화 (§12.5).

> ⚠️ **`Origin` 검증 없이 이 마일스톤을 데모하지 않는다.** 데모는 브라우저를
> 열어 둔 채로 하게 되고, 그 상태가 정확히 위험한 구성이다.

> ⚠️ **M5 의 `IS_CHANGED` 가 끝나지 않은 채로 이 마일스톤을 데모하지 않는다.**
> 완료 기준의 두 문장이 곧 §5.3 의 과소·과대 무효화 양방향이다.

## 의도적으로 뺀 것

멀티 GPU, 원격 워커, 클라우드 실행, 협업 편집, 노드 마켓플레이스, ComfyUI 워크플로 임포터.

**MCP 호출의 실시간 UI 가시화** — 외부 AI 가 그래프를 바꾸는 것을 캔버스에서
실시간으로 보는 기능. MVP 밖이다 (`design.md` §12.5). 단 **서버가 그래프 상태의
단일 소스**라는 전제는 지금부터 유지한다 — 가시화는 나중에 얹을 수 있지만 상태
소유는 뒤집기 어렵다. `run_id`(§12.6)가 나중에 붙일 관찰 지점이 된다.

**저수준 `execute_graph` MCP 툴** — 템플릿이 없는 요청의 탈출구지만, 있으면
클라이언트가 그쪽으로 흐른다 (`design.md` §12.2). 필요해지면 플래그 뒤에
추가한다 — 빼는 것보다 넣는 것이 쉽다.
