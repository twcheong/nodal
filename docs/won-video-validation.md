# 원 걷기 영상 · 눈 품질 검증

## 목적과 판정 기준

2026-09-15 사용자가 기존 영상의 눈 모양 문제를 지적했다. 파일 생성 성공과
전체 윤곽 선명도만으로 품질 완료를 판정하지 않는다. 아래 두 검증은 분리한다.

- 기술 검증: 실제 MCP 실행, 파일 디코딩, 크기·프레임 수·fps·소리·타임스탬프.
- 시각 검증: 원의 눈·얼굴 유지, 깜박임과 형태 붕괴의 구분, 전신 보행·발 접지,
  프레임 간 갑작스러운 형태 변화. 눈 부분을 약 0.2초 간격으로 확대해 확인한다.

원본 캐릭터 이미지는 로컬 `hwiwon (16).png`다. 기존 영상은 384×576,
124프레임/24fps, 16스텝, seed 7, H3 Pruned ConvRot INT8 설정이었다.
낮은 해상도 원본에서도 눈 정보가 불명확하고 Real-ESRGAN 확대가 그 경계를
강조하는 것을 동일 프레임 비교에서 관찰했다. 생성 모델 자체·양자화·인코딩 각각의
기여를 분리한 실험은 아니므로 어느 하나가 유일한 원인이라고 단정하지 않는다.

## A · 생성 해상도만 변경

첫 비교는 같은 이미지·프롬프트·seed 7·16스텝·124프레임·메모리 프로필을 유지하고
384×576을 **768×1152**로 바꾼다. 업스케일을 적용하지 않은 네이티브 출력을 검토한다.
동일 seed라도 해상도가 달라지면 노이즈 텐서가 달라져 동작·표정이 픽셀 단위로
대응하지 않는다. 같은 시간의 이미지만으로 엄격한 인과 실험이라고 주장하지 않는다.

실행 ID: `3bb815497dc54af48a4cbb74d6982460`.
조건·결과·QA 저장 경로: `outputs/h3/won-native768-a/`.

### 실행 결과와 판정

실제 MCP 실행이 성공했고 전체 소요 시간은 **2,283,884ms(38분 4초)**였다.
샘플링 15회 forward에는 28분 55초가 걸렸다. RTX 5080 16GB에서 실행됐지만
GPU 전용 메모리를 거의 모두 사용하고 공유 메모리도 사용한 관찰값이 있어,
이 시간을 다른 PC의 보장 성능으로 해석하지 않는다.

- 출력: `won-walking-native768.webm`, **768×1152**, 124프레임, 24fps, 약 5.17초.
- 전체 프레임 디코딩 성공, 타임스탬프 단조 증가, 생성 그래프 메타데이터 포함.
- Opus 48kHz 오디오 248,000샘플, RMS 약 0.0111. 무음은 아니며, 이 수치만으로
  발소리의 자연스러움이나 동기화를 판정하지 않는다.
- 시각 검토: 0~120프레임을 5프레임 간격으로, 마지막 123프레임을 추가해
  **26개 얼굴 확대**를 확인했다. 이전 384×576 생성보다 눈동자·흰자·눈꺼풀
  구분이 뚜렷하고, 검토한 프레임들에서 이전의 뭉개진 눈 경계가 크게 줄었다.
  머리·후드·귀걸이 등 캐릭터의 주요 특징도 유지됐다. 모든 중간 프레임의
  결함 부재를 보장하거나 실시간 재생의 시간적 품질을 전수 검증한 것은 아니다.
- 전신 9개 시점에서 팔을 내린 뒤 좌우 발을 번갈아 내딛는 보행을 확인했다.
  팔 스윙은 다소 작고, 일부 구간은 발끝이 화면 하단에 가까워 구도 여유가 적다.
  완벽한 관절 운동·발 접지를 검증했다고 주장하지 않는다.

**결론:** 이번 캐릭터에서는 낮은 해상도 생성 후 AI 확대보다 네이티브 768×1152
생성이 눈 보존에 유리했다. 이 원본을 결과물로 채택하고 Real-ESRGAN은 추가하지
않는다. 1080×1620 출력과 혼동하지 않는다. 같은 모델·INT8 프로필에서도 개선됐으므로
눈 문제를 양자화 하나의 탓으로 단정할 근거는 없다.

검증 파일은 같은 실행 폴더의 `qa/inspection.json`, `qa/face-sequence.png`,
`qa/walking-sequence.png`, `qa/eye-before-after.png`다. 비교 이미지의 이전/새 영상은
같은 시각을 표시하지만 동일 동작을 의미하지 않는다. 다음 실행은 저장된
`request.json`의 입력 조건을 재사용할 수 있다.

## 저장소 검증

이번 작업은 모델·제품 코드 변경 없이 MCP 생성과 검증 기록을 추가했다.
`tools/ci-local.sh` 전체 실행 결과는 통과 20 · 실패 5 · 건너뜀 10이다.
실패는 기존 로컬 트리의 `output/zimage-training` 스크립트 lint/format,
Windows JS MIME 기대값 차이, 프론트 줄바꿈에 따른 prettier/API 생성물 drift다.
해당 파일과 사용자 변경은 수정하지 않았다. 상세 로그는 실행 폴더의 `ci.log`다.

이 파일에 기록한 단일 캐릭터의 결과를 다른 캐릭터나 모든 해상도의 품질 보장으로
해석하지 않는다. 생성 영상과 원본 캐릭터 이미지·모델 가중치는 Git에 포함하지 않는다.
