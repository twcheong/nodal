# 이 매뉴얼은 누구를 위한 것인가

매뉴얼을 고칠 때마다 기준이 흔들리지 않도록 대상 독자를 못박아두는 문서입니다. 문장을 하나 쓸 때마다 "이 사람이 읽는다"를 떠올리기 위한 것입니다.

---

## 1. 대상: "일반 SEO 마케터"

### 사람

- 중소 마케팅 에이전시 또는 인하우스 마케터. **경력 1~7년.**
- 문과 출신이 많습니다. **코딩은 하지 않습니다.** 개발자와 협업해본 적은 있어도 직접 짜본 적은 없습니다.
- 엑셀은 잘 씁니다. VLOOKUP, 피벗테이블, 조건부 서식 정도는 막힘없이 합니다.
- 파워포인트로 클라이언트 보고서를 만듭니다. 디자인 감각은 있지만 시간이 없습니다.

### 하루 업무

키워드 조사 · 검색 순위 확인 · 경쟁사 콘텐츠 분석 · 블로그 기획 · 백링크 점검 · GA와 서치콘솔에서 숫자 뽑기 · **그걸 전부 보고서로 만들기.**

### 쓰는 도구

네이버 키워드도구, 블랙키위, 구글 서치콘솔, GA4, 엑셀·구글시트, 파워포인트. 여유가 있으면 Ahrefs나 Semrush.

### 아는 것 / 모르는 것

| 안다 | 모른다 |
|---|---|
| 엑셀, CSV 파일 | JSON, API, 터미널 |
| 폴더에 파일이 저장된다 | `data/raw/` 같은 경로 표기 |
| 크롬 브라우저 | 프로필, headless, 포트 |
| 로그인, 계정 | 토큰, 게이트웨이, 노드 |

### 관심사

- **이거 쓰면 내 시간이 얼마나 줄어드나.**
- 나온 결과물을 **클라이언트한테 그대로 보낼 수 있나.**
- 배우는 데 얼마나 걸리나.

### 두려움 (이게 제일 중요합니다)

- 잘못 눌러서 **뭔가 망가질까 봐.**
- 내 인스타·유튜브 계정이 **정지당할까 봐.**
- 클라이언트 자료가 **새어나갈까 봐.**
- 안 되는데 **왜 안 되는지 몰라서 창피할까 봐.**

## 2. 기술자와 무엇이 다른가

| | 기술자 | 일반 SEO 마케터 |
|---|---|---|
| **문서를 읽는 법** | 필요한 곳만 검색해서 본다 | 위에서부터 따라 한다. 막히면 **거기서 멈춘다** |
| **막혔을 때** | 로그를 보고 원인을 추측한다 | **내가 뭘 잘못했나** 생각하고 포기한다 |
| **용어** | 경로·프로세스·API가 익숙하다 | **화면에 적힌 말**로만 이해한다 |
| **필요한 것** | 정확한 스펙과 파라미터 | **왜 이걸 하는지** + 다음에 뭘 누르는지 |
| **성공 기준** | 동작하면 된다 | **클라이언트에게 낼 수 있으면** 된다 |
| **표를 볼 때** | 스펙 표를 좋아한다 | 표가 길면 건너뛴다. **문장으로 읽고 싶어 한다** |
| **경고를 볼 때** | 제약 조건으로 읽는다 | **겁을 먹는다.** 안심시켜야 한다 |

## 3. 그래서 지난 매뉴얼이 실패한 이유

첫 버전은 **앱의 구조를 따라** 썼습니다. Chat 탭 → Workflow 탭 → Dashboard 탭 → Settings 순서로요. 이건 **만든 사람의 머릿속 순서**지 쓰는 사람의 순서가 아닙니다.

마케터는 "Content 모드를 써야지"라고 생각하지 않습니다. **"이번 주까지 경쟁사 분석 넘겨야 하는데"** 라고 생각합니다.

구체적인 실패 지점:

| 문제 | 지난 버전 | 이번 버전 |
|---|---|---|
| 구성 | 탭 순서 (앱 구조) | **일감 순서** (내가 할 일) |
| 경로 | `data/reports/` 에 저장됩니다 | **Reports 폴더**에 저장됩니다 |
| 엔진 | 게이트웨이 연결, Node.js 22 | **트윅시가 켜지는 중** |
| 브라우저 | headless 방식으로 동작 | **창이 뜨지 않는 게 정상** |
| 단계 | 노드 3종, validation 노드 | **단계**, 확인하고 넘어가는 단계 |
| 파일 | JSON·XLSX·CSV 형식 지원 | **엑셀 파일**, 표 파일 |
| 설정 | Designated Paths, Guardrail | 뒤로 빼고, 필요할 때만 찾아보게 |
| 예시 | 인스타 릴스·유튜브 댓글 위주 | **SEO 실무** 중심으로 교체 |
| 표 | 곳곳에 스펙 표 | 꼭 필요한 곳만. 나머지는 문장 |

## 4. 문장 규칙

이 매뉴얼을 고칠 때 지킬 것.

1. **화면에 없는 말은 쓰지 않는다.** 게이트웨이, 프로세스, 렌더링, 파싱. 전부 금지.
2. **경로는 폴더 이름으로 부른다.** `data/reports` 가 아니라 "Reports 폴더".
3. **먼저 왜, 그다음 어떻게.** 버튼 이름부터 들이대지 않는다.
4. **겁주지 않는다.** 제약을 쓸 때는 "그래서 어떻게 하면 되는지"를 붙인다.
5. **표는 비교할 때만.** 설명은 문장으로 한다.
6. **예시는 SEO 실무에서 가져온다.** 인스타 릴스 말고 검색 순위, 경쟁사 블로그, 월간 리포트.
7. **한 문단은 세 줄을 넘기지 않는다.**
8. **롱 대시(—)는 쓴다.** 라벨과 설명을 가르거나 문장에 숨을 넣을 때 유용하다. 억지로 없애면 서술어를 새로 붙이게 되어 문장이 늘어진다. (슬라이드는 예외 — 덱에서는 여전히 금지, `CONTENT_SOUL.md`)
