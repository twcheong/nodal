# 이미지 생성 점검 및 영상 단계 준비 (2026-09-03)

기준 커밋: `87bc805`. 별도 작업 사본의 `codex/image-video-review` 브랜치에서 점검했다.

## 판정

한 장 이미지 생성의 기존 경로는 CPU 소형 모델 회귀 검사와 브라우저 스모크를 통과했다.
그러나 추가 배치 검사에서 실제 결함 두 가지를 재현했다. 따라서 원래 상태를 그대로
문제없음으로 판정하지 않았으며, 영상 생성은 아직 실행하지 않았다.

## 수정

- `EmptyLatent.batch_size=2`가 `KSampler`에서 텐서 크기 오류를 일으켰다. 잠재 배치와
  프롬프트 배치의 비율을 diffusers의 `num_images_per_prompt`로 전달하도록 수정했다.
  SD와 SDXL에서 두 장이 생성되고 서로 다른 픽셀을 갖는 회귀 테스트를 추가했다.
- `Save Image`는 두 장 배열을 받아도 첫 장만 PNG로 저장하고 성공을 반환했다.
  현재 출력 계약은 에셋 하나이므로 계약을 임의로 바꾸지 않고, 여러 장 입력은
  `image` 소켓 오류로 명시적으로 거부한다. 여러 장 일괄 저장은 아직 미지원이다.
- Windows의 `core.autocrlf`로 52개 프론트 파일이 포맷 검사에 실패했다.
  `.gitattributes`로 텍스트 LF와 Windows 배치 파일 CRLF를 고정했다.
- 엔진 테스트가 전역 프리뷰 인코더를 지워 이후 diffusion 테스트에 간섭했다.
  해당 테스트 모듈에서 인코더 레지스트리를 격리하고 원래 상태를 복구한다.
- Windows에서 심볼릭 링크 권한이 없는 경우 보안 테스트 한 건은 사유를 표시해
  건너뛴다. 실제 경로 차단 검사를 통과했다고 해석하지 않는다. Linux CI는 그대로 검사한다.
- 로컬 CI의 워크플로 파싱 단계도 별도 환경을 사용한다. 실행 중인 앱의 `.venv`를
  동기화하다 Windows 파일 잠금으로 실패하거나 diffusion을 제거하는 것을 막는다.
  Git Bash의 Windows 환경 경로와 `Scripts/python.exe`도 처리한다.

## 영상 생성의 선행 조건

현재 PC는 Intel Arc B390 GPU이며 코드의 지원 백엔드는 CPU/CUDA/MPS다.
Intel XPU 지원은 없고, 로컬 nodal 모델 폴더에는 실사용 체크포인트가 없다.
영상 생성 노드, 영상 파일 저장·재생 경로도 구현되어 있지 않다.

먼저 실행 대상이 이 Intel PC인지 별도의 NVIDIA 장비인지 정해야 한다.
이후 영상 모델과 입력(이미지→영상 또는 텍스트→영상)을 정하고,
프레임·FPS·영상 에셋 출력 계약을 구체화한다. 새 공용 타입이나 API 계약을 변경할 때는
`AGENTS.md`의 인터페이스 변경 규칙을 따른다. 이미지 배치를 단순히 영상 생성으로
표기하거나 테스트용 랜덤 이미지를 완성 영상으로 제시하지 않는다.
