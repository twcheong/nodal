# 라이선스 — Apache-2.0 (확정)

> **현재 상태: Apache-2.0 확정 (2026-08-14).**
> 저작권자는 **정태우 (twcheong99@gmail.com)**.
> 전문은 저장소 루트의 `LICENSE`, 귀속 고지는 `NOTICE` 에 있다.
> 저장소는 공개되지 않았지만 **개별 공유가 시작됐다 (2026-08-16)** — 아래 "언제 잠기는가" 참조.
> 라이선스 확정과 공개 여부는 별개다.

## 지금 지켜야 할 규칙

라이선스가 정해졌다고 규칙이 없어지는 것이 아니다. **아래 세 가지는 오늘부터가 아니라
이제부터 더 강하게 지킨다.** 예전에는 "선택지를 살려두는" 조건이었지만, 이제는
**이미 한 약속을 지키는** 조건이다.

1. **ComfyUI 코드를 복사하지 않는다.** (가장 중요 — `../AGENTS.md` 절대 규칙 1)
2. **GPL/AGPL 의존성을 추가하지 않는다.** 현재 스택은 전부 허용적이다.
3. **외부 기여를 받기 전에 DCO/CLA를 세팅한다.**

### 왜 1번과 2번이 더 중요해졌는가

**Apache-2.0 과 GPL-3.0 은 한 방향으로만 호환된다.** Apache-2.0 코드를 GPL-3.0 프로젝트에
넣는 것은 가능하지만, 그 반대는 불가능하다. GPL 코드가 nodal 에 한 줄이라도 들어오면
결합 저작물 전체가 GPL-3.0 이 되어야 하는데, 우리는 이미 Apache-2.0 으로 배포하겠다고
`LICENSE` 에 적었다. **그 순간 배포물이 라이선스 위반 상태가 된다.**

미정이었을 때는 "선택지가 GPL 로 붕괴한다"가 최악이었다. 지금은 "이미 배포한 것과
모순되는 코드가 들어온다"가 최악이다. 위반의 결과가 더 나빠졌다.

지금 이 제약을 지키는 비용은 여전히 거의 0이다 — 모델 계층은 `diffusers` 에 위임하기로
했으므로 복사할 이유가 대부분 사라졌다.

### 왜 3번(DCO)이 남아 있는가

DCO 는 라이선스 선택과 별개의 장치다. 기여자가 자기 기여를 이 프로젝트의 라이선스로
낼 권리가 있다고 서명하는 것이다. Apache-2.0 으로 정해졌으니 **서명이 가리키는 대상이
비로소 명확해졌다** — 예전에는 "미정인 무언가"에 동의하라는 이상한 요구였다.

모든 커밋에 `Signed-off-by` 가 필요하고 CI 의 `dco` 잡이 강제한다 (`dev.md` 참조).

## 왜 Apache-2.0 인가 — 결정 근거

### 1. 플러그인 생태계가 결정적이었다

nodal 은 플러그인 기반 도구다. 이 한 가지가 선택을 가장 크게 좌우했다.

- **GPL/AGPL 이었다면**: FSF 해석상 같은 프로세스에 로드되어 자료구조를 공유하는
  플러그인은 파생 저작물 → GPL 호환이어야 한다. 법적으로 다툼의 여지가 있지만
  상업적 플러그인 저자에게는 충분한 위축 효과다. ComfyUI 커스텀 노드 생태계의
  라이선스가 뒤죽박죽인 이유이기도 하다.
- **Apache-2.0 이므로**: 플러그인 저자가 원하는 대로 라이선스를 붙인다.
  `design.md` §8 의 확장 구조(M6)가 법적 회색지대 없이 성립한다.

### 2. 특허 허여 — MIT 와 갈린 지점

MIT 와 Apache-2.0 은 실질적으로 거의 같지만 **Apache-2.0 에는 명시적 특허 허여(§3)가
있다.** 이미지 생성 분야는 특허 활동이 활발한 영역이라, 기여자로부터 특허 라이선스를
함께 받아두는 쪽이 채택자에게 안전하다. 기업이 도입을 검토할 때 법무가 실제로 보는 항목이다.

비용은 MIT 보다 파일이 길다는 것뿐이다.

### 3. 스택 전체와 일관된다

`diffusers` · `transformers` · `accelerate` · `safetensors` 가 전부 Apache-2.0 이다.
모델 계층을 `diffusers` 에 위임한다는 핵심 설계 결정(`../AGENTS.md` 6번)을 고려하면,
nodal 의 무게중심에 있는 의존성과 같은 라이선스를 쓰는 것이 자연스럽다.

### 4. 포기한 것 — ComfyUI 코드 참조

Apache-2.0 을 고르면 ComfyUI(GPL-3.0) 코드를 가져올 수 없다. **이 손실은 작다.**
애초에 `AGENTS.md` 절대 규칙 1로 처음부터 복사를 금지해 왔고, 가장 복사하고 싶은
모델 계층은 `diffusers` 에 위임했다. `NOTICE-provenance.md` 가 아키텍처 참조만
있었음을 기록으로 증명한다.

### 5. 선택하지 않은 것 — AGPL

"누가 이걸 SaaS 로 팔아먹는 게 싫다"가 강한 동기였다면 AGPL-3.0 이었을 것이다.
그 경우 ComfyUI 코드도 참조 가능해진다. **그 동기보다 생태계 성장을 택했다.**
대기업이 nodal 을 가져다 닫아버리고 파는 것을 막고 싶다면 카피레프트만이 그것을
막지만, 로컬 실행형 워크스테이션에서 그 시나리오의 현실성은 낮다고 판단했다.

### 검토한 선택지 (기록)

| 라이선스 | 성격 | 특허 조항 | 판정 |
|---|---|---|---|
| MIT | 완전 허용 | ❌ | 근소한 차이로 탈락 — 특허 허여가 없다 |
| **Apache-2.0** | 완전 허용 | ✅ | **채택.** 위 1~3 |
| MPL-2.0 | 파일 단위 카피레프트 | ✅ | 중간 지대의 복잡성 대비 이득이 없음 |
| GPL-3.0 | 강한 카피레프트 | ✅ | 플러그인 생태계를 위축시킴 |
| AGPL-3.0 | GPL + 네트워크 조항 | ✅ | 위 5 |
| 듀얼 (AGPL + 상용) | 오픈코어 | ✅ | CLA 필수 — 개인 프로젝트에 과한 관리 비용 |

## 현재 의존성 라이선스 (전부 Apache-2.0 과 호환)

| 패키지 | 라이선스 |
|---|---|
| `diffusers` | Apache-2.0 |
| `transformers`, `accelerate`, `safetensors` | Apache-2.0 |
| PyTorch | BSD-3-Clause |
| FastAPI, pydantic, uvicorn | MIT |
| `@xyflow/react` (React Flow) | MIT |
| Zustand, Yjs | MIT |
| Pillow | MIT-CMU (HPND) |

MIT · BSD · HPND 는 전부 Apache-2.0 배포물에 포함할 수 있다.
**GPL 을 끌어들이는 요소가 스택 어디에도 없다.**

CI 의 `licence-guard` 잡이 세 가지를 강제한다: `LICENSE`·`NOTICE` 존재,
`LicenseRef-UNDECIDED` 잔존 없음, GPL/AGPL 표기 없음.

## 되돌릴 수 있는가 — 언제 잠기는가

**미래 버전은 아직 되돌릴 수 있다.** 단독 저작권자다. 다만 아래 표가 갱신됐다.

| 시점 | 무슨 일이 일어나나 | 상태 |
|---|---|---|
| **첫 외부 기여 수락** | **여기서 잠긴다.** 기여자 전원 동의 없이 재라이선스 불가 | 아직 없음 |
| 첫 배포 (공개든 개별 공유든) | 그때 넘긴 버전이 영구히 Apache-2.0 으로 남는다 | **발생함 (2026-08-16)** |
| 첫 GPL 코드 복사 | 배포물이 즉시 라이선스 위반 상태가 된다 | 절대 금지 |

> **개별 공유도 배포다.** Apache-2.0 §1 의 "Derivative Works ... 를 제3자에게 제공"에
> 공개 여부 조건은 없다. 한 사람에게 사본을 넘기면 **그 사본은 Apache-2.0 으로 넘어간
> 것이고 회수할 수 없다** — 받은 사람은 그 버전을 계속 그 조건으로 쓸 수 있다.
> 실질적 영향은 작다 (원래 그 라이선스로 낼 계획이었다). 중요한 것은 **이제 "아직
> 배포 전이니까"를 근거로 들 수 없다**는 점이다. 미래 버전의 재라이선스 자유는 남아 있고,
> 잠금의 결정적 시점은 여전히 **외부 기여 수락**이다.

비대칭에 주의:

- 단독 저작권자인 동안은 **미래 버전**을 어느 방향으로든 재라이선스할 수 있다
- 하지만 **이미 배포한 버전은 영구히 Apache-2.0 이다.** 회수할 수 없다
- DCO 서명이 있어도 재라이선스 권한이 생기지는 않는다. DCO 는 기여할 권리를
  확인할 뿐이고, 라이선스 변경 권한을 넘기는 것은 CLA 다. **외부 기여를 받기 시작하면
  Apache-2.0 은 사실상 최종이다**

### 참고: 라이선스 없이 공개하지 않는다

이제 해당하지 않지만 이유는 남겨 둔다. LICENSE 파일이 없는 **공개** 저장소는
"자유로운" 상태가 아니라 **전권 유보(all rights reserved)** 상태다. 기본 저작권법이
적용되어 아무도 사용·복사·수정·배포할 수 없다. `LICENSE` 를 둔 지금 이 함정은 닫혔다.

## 실무 메모

- **소스 파일에 라이선스 헤더를 붙이지 않는다.** Apache-2.0 은 `LICENSE` + `NOTICE`
  로 충분하고 (§4 는 헤더를 요구하지 않는다 — APPENDIX 는 권고다), 한국어 docstring
  이 많은 이 저장소에서 헤더는 노이즈만 키운다.
- **`NOTICE` 와 `NOTICE-provenance.md` 는 다른 파일이다.** 앞의 것은 §4(d) 가 요구하는
  법적 귀속 고지이고, 뒤의 것은 "ComfyUI 코드를 이식하지 않았다"를 증명하는 내부 기록이다.
- **서드파티가 자체 NOTICE 를 요구하면** `NOTICE` 에 절을 추가한다. 현재는 없다.
- **재배포 시** `LICENSE` 와 `NOTICE` 를 함께 전달해야 한다 (§4(a), §4(d)).
- **✅ 휠에 `LICENSE`·`NOTICE` 넣기 — 해결됨 (2026-08-16).** 예전에는 두 파일이 저장소
  루트에만 있었고, hatchling 은 각 패키지 디렉토리 안에서만 라이선스 파일을 찾으므로
  휠의 `.dist-info/licenses/` 가 비어 있었다 (`License-Expression: Apache-2.0`
  메타데이터는 그때도 정상이었다). 그 상태로 publish 하면 §4(a) 를 만족하지 못한다.

  이제 두 파일이 `packages/*` 각각에 복사되어 있고 네 `pyproject.toml` 이
  `license-files = ["LICENSE", "NOTICE"]` 로 선언한다. 확인:

  ```bash
  uv build --package nodal-core --out-dir /tmp/wheeltest
  unzip -l /tmp/wheeltest/nodal_core-*.whl | grep licenses
  ```

  **사본이므로 갈라질 수 있다.** 루트를 고치면 `packages/*` 에도 복사한다 — CI 의
  `licence-guard` 가 `cmp` 로 검사해서 어긋나면 실패한다. 심볼릭 링크는 Windows 에서
  깨질 수 있어 쓰지 않았다.
