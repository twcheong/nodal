# 한 영상 안의 캐릭터 일관성 · 조사와 적용 경계

2026-09-15. 사용자 요청은 일관성 유지 방법 조사와 이미지 생성 경로 고정이다.
아래 본문은 조사 당시의 상태를 보존한다. 이후 사용자가 1번/2번 반복 비교와
Ref2VA 다운로드·입력 확장을 승인했다. 현재 연결과 실험 상태는
[원 비교 기록](won-method-comparison.md)에 별도로 기록한다.

## 무엇을 구분해야 하나

눈이 선명한 것, 원의 원본과 닮은 것, 움직이는 동안 같은 얼굴을 유지하는 것은
서로 다른 품질이다. 기존 결과의 정적 얼굴 표본 검토만으로 세 번째 항목까지
통과했다고 답한 것은 충분한 검증이 아니었다. 사용자는 노을 강변 영상의 중간
정체성 변형을 지적했고, 해당 결과는 **시간적 정체성 일관성 미통과**로 남긴다.

H3는 영상의 잠재 표현을 함께 처리한다. 시작 이미지를 첫 순간에만 읽고 이후
잊어버리는 단순한 순차 생성으로 설명하면 부정확하다. 시작 프레임 조건은 있어도
모든 시점의 얼굴 형태를 강제로 같게 만드는 보장은 없다는 것이 현재 문제다.
공식 파이프라인의 구조는 [diffusers 0.40 H3 문서](https://huggingface.co/docs/diffusers/v0.40.0/en/api/pipelines/minimax_h3)에 있다.

## 현재 nodal에서 확인한 사실

- `packages/nodes-diffusion/src/nodal_nodes_diffusion/h3.py`는 `first_frame`과
  `last_frame`을 각각 `image`, `last_image`로 전달한다. 이미지가 있으면 `fl2va`,
  없으면 `t2va`를 선택한다. `ref2va` 입력·로딩·실행 연결은 없다.
- 실제 MCP 템플릿 `examples/templates/h3_image_video.nodal.json`은 시작 이미지
  `source`만 받는다. 마지막 이미지 소켓은 노드에 있으나 이 템플릿에는 노출되지 않았다.
- 현재 모델 폴더에는 `transformer`가 있고 `transformer_ref` 디렉터리는 없다.
  모델 인덱스에 참조용 항목이 적혀 있는 것과 가중치가 설치된 것은 다르다.
- 강변 실행 `81c8e57384424526bd2f6d6d3f785ab1`은 시작 이미지 한 장,
  768×1152, 16스텝, 124프레임/24fps, Pruned ConvRot INT8였다. 업스케일은 없다.
  인물이 점점 커져 후반에는 신발이 잘리는 구도 변화도 관찰됐다.
- 외부 ImageGen으로 시작 이미지를 두 번 편집한 것은 원본 대비 정체성 변형의
  추가 경로다. 다만 영상 **내부** 변형을 ImageGen 하나의 탓으로 단정하지 않는다.

## 유지 방법과 우선순위

### 1. 시작·끝 프레임으로 양 끝을 제약한다 — 가장 작은 다음 실험

원의 동일한 원본을 기준으로 nodal 내부 이미지 모델에서 시작·끝 이미지를 준비한다.
두 이미지의 얼굴·옷·조명·인물 크기·카메라 각도는 맞추고 보행 자세만 호환되게 한다.
영상 자체가 이미 변형한 마지막 얼굴을 무비판적으로 끝 기준으로 재사용하지 않는다.

H3 FL2VA는 양 끝 이미지 사이의 단일 장면 경로를 기술하는 방식을 지원한다.
이는 끝의 구도 이탈을 줄일 후보이지, 중간 얼굴 고정을 보장하는 장치가 아니다.
현재 노드 소켓을 연결하는 그래프 실험은 가능하지만 실제 끝 이미지 GPU 실행은
아직 미검증이며, 기존 MCP 템플릿을 확장하려면 그 변경을 별도로 수행해야 한다.
[공식 기본 프롬프트 가이드](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

### 2. 다중 캐릭터 참조를 조건으로 넣는다 — 구조적으로 더 직접적인 후보

H3에는 FL2VA와 구분되는 Ref2VA 모델이 있다. 원의 정면 얼굴·3/4 얼굴·전신처럼
서로 모순되지 않는 원본 참조들을 캐릭터 정의에 묶고, 강변 참조는 환경 역할로
분리하는 방식을 검토한다. 한 이미지는 외모, 다른 영상은 동작 역할로 지정할 수도 있다.
참조 역할을 명시하는 것이 중요하며, 프롬프트에 이미지 번호만 적고 실제 입력을
전달하지 않는 것은 참조 조건이 아니다.
[공식 모델 카드](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/README.md),
[공식 참조 프롬프트 가이드](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)

**이 프로젝트에서의 제안이지 원 캐릭터에 대한 실측 성공 결과는 아니다.**
Ref2VA는 참조 대상과 똑같은 화면 배치를 고정하는 모드도 아니다. 현재 nodal에는
참조 transformer·입력·Pruned 로더 대응이 없으므로 단순 옵션 변경으로 켤 수 없다.
FL2VA와 Ref2VA를 동시에 섞거나 임의 중간 키프레임을 넣는 기능도 현재 지원으로
주장하지 않는다. 외부 커스텀 노드 코드는 가져오지 않았다.

### 3. 동작과 카메라의 변화량을 줄여 실패 요인을 분리한다

이 항목은 공식 품질 보장이 아닌 **다음 실험 설계 제안**이다.
카메라 쪽으로 크게 접근하는 보행 대신 거리 변화가 작은 보행, 느린 동작,
작은 머리 회전, 일정한 조명으로 시작한다. 카메라 추적·인물 접근·팔 내리기·보행을
동시에 요구하기보다 처음부터 팔이 내려간 시작 자세를 준비한다.
공식 가이드는 카메라 동작·범위·속도를 명시하고 시작 상태부터 동작을 연결하도록
안내한다. 프롬프트만으로 카메라가 실제로 고정되는지는 결과에서 검사해야 한다.
[공식 기본 프롬프트 가이드](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

### 4. 해상도·스텝·seed는 보조 변수이지 정체성 잠금이 아니다

- 네이티브 768×1152는 기존 눈 디테일 개선에 유효했으므로 유지할 후보지만,
  캐릭터 일관성 완료 기준을 대신하지 않는다.
- seed 고정은 재현·비교용이다. 첫 프레임과 마지막 프레임을 함께 넣으면 조건 노이즈
  추출도 바뀌므로 같은 seed라도 동일한 동작을 기대하지 않는다.
- H3는 guidance-distilled이며 일반적인 `guidance_scale`이나 `negative_prompt`
  조절 기능이 없다. CFG를 올리면 해결된다고 안내하지 않는다.
- 16→30스텝 비교는 나중의 통제 실험이다. 15→29 forward로 계산량이 늘지만
  정체성 개선 보장은 없다. INT8·Pruned의 영향도 별도 대조군 없이 단정하지 않는다.
- 현재 nodal 최소 길이는 약 5.17초다. 지원하지 않는 2초 생성으로 해결한다고
  말하지 않는다. 프레임별 독립 이미지 보정·얼굴 복원은 깜박임을 새로 만들 수 있어
  시간축 일관성 검증 없이 해결책으로 채택하지 않는다.
  [diffusers H3 문서](https://huggingface.co/docs/diffusers/v0.40.0/en/api/pipelines/minimax_h3),
  [시간적 일관성 연구](https://arxiv.org/abs/1808.00449)

원본 3D 캐릭터와 리그를 실제로 가지고 있다면, 같은 메시·재질을 렌더하는 보행
애니메이션이 생성형 영상보다 정체성 제어에 직접적인 별도 경로다. 현재 그런 자산이
확인된 것은 아니며 이 조사에서 도구나 작업 방식을 바꾸지 않는다.

## 다음 검증 절차 — 아직 실행하지 않음

1. nodal 내부에서 준비한 같은 원본 기반 참조를 고정한다. 배경 편집 전후의 얼굴도
   별도로 비교한다. 외부 생성 이미지를 새 정체성 기준으로 삼지 않는다.
2. 768×1152·124프레임·16스텝과 단순 보행을 고정하고 시작만/A, 시작+끝/B를 비교한다.
   seed 7만 보고 일반화하지 말고 예를 들어 7·19·31의 작은 반복으로 재현성을 본다.
3. 양 끝이 맞아도 중간이 변하면 통과시키지 않는다. 이후 Ref2VA를 로컬에 연결하는
   별도 작업을 검토한다. 새 가중치·라이선스·메모리 요구를 확인한 뒤 진행한다.
4. 원본 및 생성 첫 프레임 대비 0.25초 간격의 얼굴을 **크기·각도를 고려해** 비교하고,
   의심 구간은 인접 프레임과 실시간/느린 재생으로 확인한다. 눈 간격·턱·코·입·헤어라인,
   귀걸이·후드·신체 비율과 배경 구조를 각각 판정한다. 단순 밝기 변화·깜박임은 구분한다.
5. 얼굴 임베딩 유사도는 보조 지표에 한정한다. 스타일화된 3D 얼굴에 검증되지 않은
   임계값으로 자동 통과시키지 않는다. 전체 평균이 좋은 것보다 **가장 나쁜 중간 구간**을
   우선 확인하고, 최종 수용은 사용자 검토와 구분해 기록한다.

## 이미지 생성 경로 고정 결과

`AGENTS.md` 절대 규칙 0에 **nodal 내부 이미지 모델만 사용**을 기록했다.
영상용 시작·끝 이미지, 배경 편집, 포즈·구도 수정도 포함하며 외부 ImageGen/API로
자동 대체하지 않는다. CLAUDE.md는 AGENTS.md를 이미 참조하므로 중복 규칙은 쓰지 않는다.
이것은 이 저장소의 에이전트 작업 규칙이며 앱 전체의 외부 도구를 기술적으로
비활성화한 것은 아니다. 기존 영상·이미지는 삭제하지 않는다.

현재 서버 등록 목록은 기본 `diffusion.LoadCheckpoint`·`KSampler` 등만 포함하며,
FLUX/ZImage/Qwen/LongCat 이름의 전용 노드는 보이지 않았다. 해당 모델 폴더 및
일부 MCP 템플릿이 있다는 사실만으로 내부 편집 실행 준비 완료를 주장하지 않는다.
다음 이미지 작업 전에 실제 노드·모델 연결 상태를 점검한다.
