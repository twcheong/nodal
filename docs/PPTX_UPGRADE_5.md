## 1. 이번 차수의 성적표

일곱 차수 중 다섯(12·13·15·16)이 버그 수정이었고, 그 여섯 증상이 **전부 우리 코드가 만든 문제**였다. 벤치마크 격차가 아니라 자체 결함이라는 뜻이고, 4차 문서의 비율(7중 4)보다 나빠졌다 — 기능을 붙일수록 자기 코드끼리 어긋나는 지점이 늘어난다는 신호다. 나머지 둘(17·18차)은 기능이 아니라 **화면의 청중을 가른** 작업이다.

| 증상 (유저 실물) | 근원 | 차수 |
|---|---|---|
| 한국어 덱이 통째로 영어로 번역됨 | 언어 샘플이 **앱이 쓴 영어 메시지**를 잡음 | 12 |
| 값 세 줄이 아래 행을 관통 | kv 행 높이 고정 + **기하 검사가 잉크를 박스로 잘라냄** | 13 |
| 같은 슬라이드가 중복되고 3번은 안 고쳐짐 | 시트는 1-based, patch `index` 는 0-based | 13 |
| 덱이 촌스러움 | `night` headFont 가 **고정폭 코드 페이스**(Consolas) | 13 |
| 좌우 두 섹션이 안 맞음 | 공유 축이 없음(카드는 고정 높이, 좌측은 헤딩 없음) | 15 |
| 숫자가 중앙이 아니고 5번이 잘림 | stat 페인터가 **자기 rect 를 무시**하고 고정 오프셋 | 16 |

## 2. 12차 — 언어 교정이 덱을 영어로 번역했다 (d3200a8)

**증상:** *"자동으로 영어 강제되는 거 같은데? 유저 언어가 한글이면 한글, 중국어면 중국어여야 됨."*

**근원:** Content 모드는 모델에게 **사용자로서** 말한다. 시각 QA 이미지 메시지도, 렌더 실패 재시도 메시지도 `role:'user'` 로 대화에 쌓이고 **둘 다 영어**다. 언어 교정기는 "마지막 user 메시지"로 목표 언어를 정하므로, QA 라운드 뒤에 덱이 커밋되면 샘플이 영어로 잡힌다 — 한국어 덱 전체가 번역된다.

**수정:** `CopilotMessage.appAuthored` 를 두고 `sendMessage(text, { appAuthored: true })` 로 표시. 샘플은 `appAuthored` 가 **아닌** 마지막 user 턴에서만 뽑는다. 채팅 교정기도 같은 잠재 버그였으므로 같이 고쳤다.

**방어 두 겹 더** (모델 한계에 대한 보험이지 근원 수정은 아님): 배치 교정 프롬프트에 "너는 오염을 고치는 것이지 번역하는 게 아니다", QA 메시지 말미에 "이 지시는 영어지만 덱은 방금 쓴 언어 그대로".

> 교훈: **앱이 사용자 자격으로 말하면, 그 발화는 사용자 신호가 아니라는 표식을 반드시 달아야 한다.** 표식이 없으면 사용자 신호를 읽는 모든 기능이 앱의 목소리를 사용자로 오인한다.

## 3. 13차 — 실물 4건 (4eece3b)

**① `night` 팔레트·폰트.** 유저가 첨부한 팔레트(`0A0A0C` / `1F2A24` / `3E5A4C` / `D4AF37` / `F2F6F3`)로 교체. 그리고 headFont 가 **Consolas** — 고정폭 CODE 페이스였다. 덱 전체를 터미널 목소리로 만들고 한글 옆에서 특히 나빴다. "촌스럽다"의 정체가 이거다. 라이트 테마들이 이미 쓰는 세리프(Cambria)로 교체, 전 롤 대비 8.7:1 이상 실측.

**② kv 행 겹침.** span-4 카드의 값 칸이 ~1.2" 인데 `206 followers · 포트폴리오 부모` 같은 값은 autofit 바닥(60%)에서도 한 줄에 안 들어가 3줄로 풀렸고, 행 높이는 **0.36" 고정**이라 아래 행을 그대로 관통했다. 이제 행을 누적 배치하고(구조적으로 겹칠 수 없다) 한 줄에 못 앉는 행은 키 위·값 아래로 스택한다. `measureBlock` 도 같은 판정을 미러. 실측: overflow 5건 → **shrunk 5건(무손실)**.

**③ 기하 검사가 왜 이걸 못 잡았나** — `inkRect` 가 잉크 높이를 **박스로 클램프**하고 있었다. 박스를 넘친 텍스트가 이웃과 충돌하는 케이스인데, 클램프가 정확히 그 케이스를 전부 가렸다. 해제 후 픽스처 오탐 0(유일한 1건은 의도적 overflow 픽스처).

**④ 슬라이드 중복의 근원** — QA 시트와 페이지 배지는 **1-based**, patch 의 `index` 는 **0-based**. 모델이 시트에서 "3번"을 보고 `index:3` 을 쓰면 4번에 착지한다 → 3번은 그대로 남고 4번이 덮여 중복. `page`(1-based) 필드 신설: **변환이 없으면 어긋날 수도 없다.** `index` 는 하위호환 유지.

## 4. 14차 — 경고를 UI 에서 완전히 제거 (fec755f)

13차에서 "QA 라운드가 도는 동안만 접기"로 처리했는데, 요청은 *"UI 에 안 보여도 된다"* 였다. **조건부가 아니라 표면 자체를 뺐다** — 하단 경고 스트립 · 썸네일 ⚠ 뱃지 · "Font size auto-adjusted in N places" 줄 · 이제 불필요해진 `qaPending` 배선.

근거는 청중이다. `overflows its box by 0.27in` 을 보고 사용자가 할 수 있는 일이 없고, 같은 목록이 첫 생성 직후 QA 라운드로 모델에게 가서 patch 로 돌아온다. 모델 채널(`warningsToText`, 툴 반환값)은 정밀도 그대로.

> 이 결정이 17차의 전제가 된다: 사람용 표면이 비었으니, 거기에 사람이 **실제로 조작할 수 있는 것**을 놓아야 한다.

## 5. 15차 — 한 페이지 안의 두 섹션 + 페이지네이션 4종 (1274b55)

**질문:** *"두 개가 다른 섹션 디자인인데 한 페이지면 어떻게 alignment 할지 코드는 없었어? 페이지네이션 스타일도 하나만 있어 보임."*

**① summary `split`.** 좌 체크리스트와 우 카드가 한 페이지에 있는데 **서로 맞춰지는 축이 없었다.** 카드는 `y=1.6` 에서 4.6" 고정(밴드를 안 채움), 좌측은 헤딩이 없어 카드의 'Next Steps' 헤딩이 첫 체크 항목 **위에** 떠 있었다 — 두 페이지를 붙여 놓은 것처럼 읽힌다. 이제 두 열이 **헤딩 baseline 하나(`headY`)와 첫 항목 baseline 하나(`itemsY`)를 공유**하고, 좌측에도 'Takeaways' 헤딩을 세웠다. 카드가 밴드를 채워 페이지 하단을 정의하고 closing/contact 도 밴드 기준으로 앉는다.

**② 페이지 배지 4종.** 모든 슬라이드에 찍히는 유일한 요소인데 회색 알약 하나뿐이었다 — 가장 많이 반복되는 것이 가장 안 변하는 것이었다. `StyleRecipe.badge` 로 가른다: `sharp`=plain(맨 숫자) · `soft`=pill(기존) · `rounded`=dot(액센트 원 + 반전 숫자) · `pill`=frame(아웃라인). **새 payload 필드가 아니라 기존 style 축에 얹었다** — 덱 성격에 따라 자동으로 갈리고 결정론도 유지된다.

베이스라인 addText 4243→4262(**+19**) = summary split 슬라이드마다 새로 생긴 'Takeaways' 헤딩 수와 정확히 일치.

## 6. 16차 — 카드를 뚫고 흘러내리던 stat + 스샷 순서 (4dc31b7)

**증상 셋이 한 버그였다:** 글자 겹침 · 박스 안 숫자가 중앙이 아님 · 5번 슬라이드가 잘림.

**X-ray:** 카드는 `y=1.40 h=1.02`, 내용은 `1.60 → 3.85`(**2.25"**). 그리드는 행이 안 맞으면 비례 축소하는데(`grid.ts` pass 3) `paintBlock('stat')` 이 **값 1.35" · 라벨 +1.5 · 서브라벨 +2.1 을 하드코딩**하고 있었다. 자기 카드를 뚫고 다음 행으로 흐르고, 그게 누적돼 5번째 행이 `y=8.54`(7.5" 페이지)로 떨어졌다. 숫자가 중앙이 아니던 것도 같은 원인 — 값 상자가 카드보다 커서 중심이 아래로 밀렸다.

**수정:** 높이를 `r.h` 에서 비례로 뽑는다(`subH`/`labH`/`valH`). 실측: 카드 `1.02"` → 내용 하단이 **정확히 카드 하단**. `funnel` 밴드도 같은 클래스(고정 0.78")라 함께 비례화.

**② 순서 — 유저 가설이 맞았다.** *"이거 아마 번역하고 나서 스샷 찍고 피드백이 가야 될 듯?"* 언어 교정과 시각 QA 를 각자 `void async` 로 띄워 **경합**시키고 있었고, 모델은 **번역 이전 레이아웃**을 찍은 시트를 보고 QA 했다. 한국어는 길이가 달라 줄바꿈이 바뀌므로 **모델이 본 화면과 최종 화면이 서로 다른 덱**이었다. `correctLanguage()` 가 교정본을 반환하고 QA 가 그걸 `await` 한 뒤 시트를 굽도록 직렬화 — 모델이 보는 화면 = 최종 화면. QA 를 안 도는 경로(patch)에서는 교정만 단독 실행.

## 7. 17차 — 좌측 패널을 디자인 조작반으로 (본 차수)

**요청:** *"왼쪽 패널 저거 둘 다 굳이 보여줄 필요 없으니까 없애고, 리소스 덜 잡아먹는 것 중에 PPT 제작 옵션들을 비주얼적·직관적으로 보여줄 수 있는 걸로 채워줘."*

**걷어낸 것:** 구조 리포트 · 슬라이드별 경고 · 스펙 JSON 전문(`DeckDiagnostics.tsx` 삭제). 14차에서 프리뷰의 경고를 뺐으니 좌측만 남아 있었는데, 그것도 **모델용 정보**였다 — 같은 목록이 QA 라운드로 모델에게 간다. `deckWarnings.ts` 는 이제 모델 채널 전용이라 사람용 분류(`splitWarnings`/`isMinor`)를 제거했다.

**채운 것 — `DeckDesigner.tsx`.** 핵심 성질은 **조작 전부가 로컬 재계산**이라는 것이다. `buildDeck` 이 순수 함수라 스펙 한 필드만 갈아 다시 그리면 끝이고(모델 왕복 0 · 파일 쓰기 0), 그래서 **옵션 이름이 아니라 결과를 고르게** 할 수 있다 — 타일마다 "그 옵션으로 실제로 그린 지금 이 슬라이드"가 들어간다.

| 섹션 | 무엇 | 클릭하면 |
|---|---|---|
| **Palette** | 테마 10종, 각 타일 = 그 팔레트로 그린 현재 슬라이드 | `theme` 교체 (+ 얼굴 동결, 아래) |
| **Shape** | 스타일 4종 — 라운딩·마진·갭 + **페이지네이션 4종이 눈에 보인다**(15차의 결과물) | `style` 교체 |
| **Brand tint** | 프리셋 8색 + 네이티브 피커 + Clear | `brand` → `deriveTheme` 가 어떤 팔레트든 재도색 |
| **Slide N** | 그 장의 **얼굴 축** — `variant` 전 후보, chart 면 `chartType` 까지 | 그 슬라이드만 교체 |

**설계 결정 네 가지:**

1. **얼굴 동결(freeze).** 시드는 `제목 + 테마`(`deckSeed`)라, 테마를 바꾸면 **variant 가 비어 있는 모든 장의 레이아웃이 같이 굴러간다** — 색만 바꿨는데 덱이 흔들린다. 그래서 테마 교체 시 지금 화면에 보이는 얼굴을 스펙에 얼려 넣는다(`slides: rotateVariants(...)`). 실측: 동결 없이 34장 중 1장이 얼굴 변경, 동결 후 **0**.
2. **옵션 필드는 이름으로 고른다**(`OPTION_FIELDS = ['variant', 'chartType']`). `FIELD_SIGS` 의 시그니처 패턴으로 자동 추출하면 `section.number` 의 `'number|string'` 이 걸린다 — 그건 열거형이 아니라 **타입 합집합**이고, 표는 둘을 구분하지 못한다.
3. **선택 슬라이드를 위로 올렸다.** 좌측 타일이 "지금 보고 있는 그 장"을 그려야 비교가 성립하므로 `selected` 를 `DeckPanel` 지역 상태에서 `CopilotView` 로 옮겨 두 패널이 공유한다.
4. **커밋 전 검증.** 디자인 변경도 `buildDeck` 을 통과해야 커밋된다 — 모델 스펙에 적용하는 가드와 같은 규칙(로컬 편집이라고 예외를 두지 않는다).

**이게 답이 되는 예전 질문:** *"왜 계속 overview 는 하나 옵션뿐이야?"* — 이제 그 장을 고르면 `list / sidebar / cards` 가 **그려진 채로** 나란히 뜬다.

## 8. 18차 — UX 정리: 사람이 볼 것 / 모델이 볼 것

다섯 요청이 같은 원칙의 다섯 얼굴이었다: **앱↔모델 배관을 사람 화면에서 치운다.** ①②는 배관을 요약해 보여주는 것이었고, ③은 요청이 한 번 더 와서 **왕복 자체를 없앴다** — 요약도 배관이다.

**① 채팅에서 스펙 JSON 제거.** 슬라이드 한 장 수정을 누르면 앱이 모델에게 보내는 메시지는 `Fix ONLY slide 4 (0-based index 3): … Its current spec: {…} … Reply with exactly one deck-patch block` 이고, **그게 그대로 사용자 버블에 찍히고 있었다.** 모델 답장도 마찬가지로 `{"page": 3, "slide": {"kind": "stats", …}}` 를 통째로 보여줬다.

- 보내는 쪽: `sendMessage` 에 이미 있던 `displayText` 를 쓴다(자동 리뷰 스캐폴딩 은닉과 같은 통로) — 모델은 전체를, 사람은 `✎ Slide 4 — 여기 글자 넘치는 거 수정 좀` 만 본다. 렌더 실패 재시도도 한 줄로(`⚠ A slide didn't render…`). 자동 검증 라운드도 여기서는 한 줄 요약이었는데, ③에서 **아예 침묵**으로 바뀐다.
- 받는 쪽: `stripDeckBlocks` + 신설 `summarizeDeckBlocks`. 산문은 그대로 두고 블록은 **카드**로 바꾼다 — 교체는 **그 슬라이드를 실제로 그려서**(`SlidePreview`) 보여주고, 삭제는 `✕ Slide 6 removed`, 전체 스펙은 `◧ Deck · 17 slides`.
- 스트리밍 중 **아직 안 닫힌 펜스**도 지운다. 그러지 않으면 완성 전 몇 초 동안 JSON 이 한 글자씩 찍히는 걸 그대로 본다.
- 함정 하나: 삭제(`slide: null`)와 '깨진 slide' 를 같은 모양으로 만들면 후자를 "삭제했음" 으로 그리게 된다 — 깨진 블록은 요약에서 건너뛴다(에러 표면은 `parseDeckBlock` 쪽).
- 성능: `summarizeDeckBlocks` 를 `content` 로 메모한다. 스트리밍 중엔 전 버블이 매 틱 재렌더되므로, 매번 새 note 객체를 만들면 썸네일이 매 틱 `buildDeck` 을 다시 돈다.

**② 되돌리기.** 모델 수정 · 언어 교정 · 디자인 패널 편집이 전부 같은 스펙을 갈아끼우는데 되돌릴 방법이 없었다. 대화별 스택(깊이 20, 세션 메모리 전용). 핵심 규칙: **되돌릴 지점은 커밋하는 쪽이 명시한다**(`commitDeck(convId, next, undoFrom)`). 커밋 시점에 이전 값을 자동으로 밀어 넣으면, 한 턴이 두 번 커밋하는 경로(모델 스펙 → 언어 교정)에서 undo 를 두 번 눌러야 원래로 돌아간다. 언어 교정은 지점을 만들지 않는다 — **undo 한 번 = 그 턴 취소.**

**③ 자동 검증을 통째로 숨긴다 — 첫 덱은 검증 뒤에 처음 보여준다.** ①로 `displayText` 를 달아도 유저는 여전히 앱의 영문 QA 지시문 한 덩어리와 모델의 영문 답장을 봤다. 요청은 *"이거 유저가 안 보게, 애초에 검증 이후에 보여주면 안 되나 처음 꺼를"* — 요약이 아니라 **왕복 자체를 전사에서 빼는 것**이다.

- `sendMessage({ silent: true })` — 보낸 것도 받은 것도 대화에 남지 않는다(`silentTurns`, 대화당 하나, 다음 어시스턴트 메시지가 소비). 구독자(`CopilotView`)에게는 그대로 전달돼야 결과가 적용된다. 침묵 턴이 에러로 죽으면 에러 버블도 띄우지 않는다 — 사용자가 하지 않은 질문의 에러다. 단, **플래그는 반드시 걷는다**(안 그러면 다음 정상 답장이 삼켜진다).
- **검증 홀드** — 첫 `deck-spec` 은 커밋하지 않고 잡아 둔다(`deckHoldRef`). 언어 교정 → 시트 렌더 → 침묵 QA 발송 → **답장의 patch 까지 적용한 뒤** 한 번에 커밋한다. 그 사이 패널은 "Checking every slide…". 예전엔 초안이 먼저 뜨고 몇 초 뒤 눈앞에서 슬라이드가 바뀌었다.
- 홀드가 덱을 인질로 잡으면 안 된다: 시트 실패 → 즉시 확정 · 답장 없음 → **90초 타임아웃** 후 확정 · QA patch 가 깨짐 → 조언을 버리고 원본 확정(되묻지 않는다 — 그 재시도는 화면에 나타날 곳이 없다).
- **검증 중 전송 금지**(컴포저가 `Checking…`). 이 몇 초 사이에 사용자가 메시지를 보내면 그 답장이 검증 답장보다 **먼저** 도착해 침묵 처리에 먹힌다 — 사용자의 답이 사라지는 사고다. 순서를 못 맞출 바엔 입구를 닫는다.

**④ Export 후 바로 열기.** 저장만 하고 경로 문자열을 보여줬다(사용자가 Finder 로 찾아 들어가야 했다). 성공 시 상대경로를 들고 있다가 `Open`(기본 앱) / `Show in folder` 를 건다 — 기존 `open-file` · `reveal-in-finder` IPC 재사용(둘 다 워크스페이스 밖 거부). 되돌리기를 누르면 둘 다 치운다: 내보낸 파일은 지금 화면의 덱이 아니다.

**⑤ 슬라이드에서 롱 대시 추방.** 요청은 *"프롬프트에 em dash 쓰지 말아 달라는 거 추가 가능?"* 였고, 프롬프트에만 넣으면 샌다는 걸 이 문서가 이미 세 번 기록했다(디바이더 3회). 그래서 **프롬프트 + 코드** 둘 다:

- 프롬프트(`CONTENT_SOUL.md` Phase 4 · `pptx.tskill` TEXT BUDGETS): 슬라이드 텍스트에 `—`/`–` 금지, 용어·범위의 평범한 하이픈(`A-B`, `2024-2025`)은 허용. **"지금 읽고 있는 이 문서가 롱 대시 투성이인 것은 문서 스타일이지 덱 카피가 아니다"** 를 명시했다 — 모델은 지시문의 문체를 그대로 배운다.
- 코드(`stripLongDashes`, `buildDeck` 최상단): SVG 프리뷰 · pptx 내보내기 · QA 시트가 **전부** buildDeck 을 지나므로 강제 지점이 하나다. 언어 교정과 같은 walk 를 재사용해 **프로즈 문자열만** 건드린다(`variant`·아이콘 id·경로는 손 못 댐). 안 바뀌면 **같은 객체를 반환**한다 — 디자인 타일이 buildDeck 을 수십 번 부르는데 매번 클론을 뜨면 안 된다.

**여기서 하나 배웠다: 스펙만 씻는 것으로는 부족했다.** 롱 대시의 출처가 둘이었다 — 모델이 쓴 스펙, 그리고 **페인터가 스스로 조립한 텍스트**(`quote` 의 `— 이름`). 후자는 payload 를 아무리 씻어도 안 지워진다. 그래서 검사도 스펙이 아니라 **완성된 디스플레이 리스트**를 훑는다(`structure-check`, 31 픽스처 전 요소). 실제로 이 검사를 먼저 통과시켰다가 픽스처를 다시 훑어보고 인용 귀속 두 곳을 찾았다.

## 10. 남은 것

4차 문서 §11 의 항목이 그대로 유효하다 — 특히 **앱 재시작 후 E2E**(툴 설명은 스폰 시점에 읽힌다): 디바이더 0장 · 새 페이지 타입(bleed/icon rows) 채택 · `page` 패치 필드 사용 · 삭제 패치 실제 사용 · 언어 교정 실호출 품질(`[correct-language-batch]` 로그) · PowerPoint/Keynote 실파일 렌더(chevron·ring·bleed).

**이번 차수에서 새로 생긴 것:**

- 디자인 패널의 편집은 **모델이 모른다.** 사용자가 테마를 바꾼 뒤 채팅으로 수정을 요청하면 모델은 바뀐 스펙을 보고 작업한다(스펙이 진실이므로 정합은 맞다). 다만 "왜 색이 바뀌었지" 를 모델이 설명하지는 못한다 — 필요해지면 편집을 시스템 발화로 알리는 배선이 다음 후보다.
- 얼굴 동결로 스펙에 `variant` 가 명시된다. 이후 모델 patch 가 그 장을 통째로 교체하면 자기 variant 로 덮이므로 충돌은 없지만, 스펙 JSON 이 조금 더 장황해진다(더 이상 화면에 안 보이므로 실해는 없다).
- **되돌리기는 세션 메모리 전용**이다. 앱을 껐다 켜면 '지금 덱'만 남는다(localStorage 에는 현재 스펙만 저장). 재시작을 넘겨야 한다면 스택도 대화별로 영속해야 한다.
- `displayText` 로 숨긴 원문은 **재개 트랜스크립트 seed 에도 안 들어간다**(저장되는 건 표시 텍스트다). 진행 중 세션에는 영향이 없지만, 대화를 오래 뒤에 재개하면 모델이 "그때 그 슬라이드의 원본 스펙"을 기억하지 못한다 — 기존 auto-review 스캐폴딩과 같은 트레이드오프.
- 채팅의 덱 썸네일은 **현재 덱의 테마/스타일**로 그린다. 나중에 테마를 바꾸면 예전 답장의 썸네일도 새 팔레트로 다시 그려진다(그 시점의 스냅샷이 아니다).
- 롱 대시는 **렌더 시점에** 걷힌다 — 스펙에는 모델이 쓴 `—` 가 남는다. 프리뷰·pptx·QA 시트가 전부 `buildDeck` 을 지나므로 사용자가 보는 곳에는 없지만, 스펙을 그대로 내보내는 새 경로를 만든다면 거기서 한 번 더 씻어야 한다. 반대로 모델이 롱 대시를 계속 쓰는지는 `deck-spec` 원문으로 확인할 수 있다(프롬프트 규칙의 효과 측정).

## 11. 이 문서 묶음의 결론 한 줄

12–18차에서 다시 확인된 것: **프롬프트로 못 고치는 건 계약으로 고치고**(1-based `page`, `appAuthored`), **계약으로 못 고치는 건 기하로 고치고**(비례 높이, 누적 행), **사람이 고칠 수 있는 건 화면에 조작으로 놓는다**(디자인 패널·되돌리기·Open). 그리고 **사람이 고칠 수 없는 건 화면에서 치운다**(경고·스펙 JSON). 넷 다 "다 보여주고 사용자가 판단하게 하자"의 반대편에 있다.
