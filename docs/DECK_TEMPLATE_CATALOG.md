# 덱 템플릿 카탈로그

**무엇**: Twixy가 지금 만들 수 있는 슬라이드 템플릿 전체 목록.
**누가 읽나**: 제품·디자인·세일즈·CS. 엔지니어 전용 문서가 아니다.
**언제 보나**: "이런 덱 만들 수 있어요?" 에 답할 때, 디자인을 손보기로 결정할 때, 고객이 특정 레이아웃을 요구할 때.

> 기술 구현은 [PPTX_DECK_GENERATION.md](PPTX_DECK_GENERATION.md)에 있다. 이 문서는 **무엇이 있고, 언제 쓰고, 바꾸려면 얼마나 드는가**만 다룬다.
> 기준일: 2026-08-15 (브랜치 `feature/pptx-skill-upgrade` — 고도화 2차 반영)

## 1. 한 장 요약

덱 하나는 **네 겹**으로 만들어진다. 넷은 서로 독립이라 자유롭게 섞인다.

| 층 | 무엇을 정하나 | 선택지 | 적용 범위 |
|---|---|---|---|
| **목적** | 덱의 페이지 구성(어떤 장이 어떤 순서로) | **6종** — 제안·보고·의사결정·정렬·분석·교육 | 덱 전체에 하나 |
| **테마** | 색 · 글꼴 | **7종** + 브랜드 색 파생 | 덱 전체에 하나 |
| **스타일** | 모서리 둥글기 · 여백 · 간격 | **4종** | 덱 전체에 하나 |
| **페이지** | 각 장의 뼈대 | **15종** → 고정 얼굴 **38개** + 자유 조판 1종 | 장마다 다르게 |

- 얼굴이 여러 개인 종류가 5종 → **11종**이 됐다. 이제 트래픽이 몰리는 차트·불릿·비교·표·타임라인·본문도 각각 2~4개 얼굴을 갖는다.
- 얼굴을 지정하지 않으면 **덱마다 자동으로 다르게** 배정된다(같은 덱 안에서는 수정해도 안 바뀜). 같은 종류가 반복돼도 얼굴이 겹치지 않는다.
- 고객 **브랜드 색 하나**를 주면 배경·본문·카드·차트 5색까지 전체 팔레트가 파생된다(가독성 자동 검증).
- 자유 조판에는 **아이콘 68종**(성장·고객·채널·일정 등 마케팅 세트)이 들어간다.
- **AI가 자기 덱을 이미지로 보고** 넘침·겹침·단조로움을 스스로 고친 뒤 내놓는다(덱당 1회).

## 2. 테마 7종 — 색과 글꼴

테마는 **주제**로 고른다. 업종이 아니라 덱의 성격에 맞춘다.

| 테마 | 성격 | 어울리는 일 | 제목 글꼴 | 기본 스타일 |
|---|---|---|---|---|
| `twixy` | Twixy 브랜드 퍼플. 밝은 배경 | 아래 어느 것도 안 맞을 때만 | Trebuchet MS | soft |
| `petrol` | 청록 + 따뜻한 크림 배경. 잡지 느낌 | 에디토리얼 리포트, 월간 리뷰 | Georgia | soft |
| `navy` | 감청 + 골드. 가장 격식 있음 | 금융, B2B, 임원 보고 | Cambria | sharp |
| `vivid` | 파랑 + 주황. 대비 강함 | 테크, 스타트업, 스포츠, 론칭, 소셜·에이전시 | Arial Black | rounded |
| `earth` | 초록 + 테라코타 | 식음료, 자연, 뷰티, 웰니스, 지속가능성 | Georgia | soft |
| `charts` | 데이터 전용 5색 팔레트 내장 | 통계·데이터 중심 리포트 | Calibri | sharp |
| `night` | **유일한 다크 테마.** 검정 배경 + 금색 | 키노트, 테크 론칭, 프리미엄 | Consolas | sharp |

**알아둘 것**
- `charts`만 차트 전용 5색 세트(청록·노랑·주황·주홍·짙은청)를 따로 갖는다. 나머지 테마의 차트는 액센트색에서 자동으로 만들어진다.
- `night`는 배경이 어두워서 글자·선 색이 전부 자동으로 뒤집힌다. 다크 프리셋은 이것뿐이지만, `night` + `brand` 조합으로 **어떤 브랜드 색이든 다크 덱**을 만들 수 있다.
- 고객 브랜드 색은 두 단계로 지원한다: `brand`(hex 하나로 배경·본문·카드·차트까지 전체 팔레트 파생, 가독성 자동 보정) 또는 `accent`(액센트색만 덮어쓰는 구형 방식).
- **없는 테마 이름을 쓰면 즉시 에러가 난다.** 조용히 기본 테마로 떨어지지 않는다 — 예전에 그랬다가 "옛날 디자인 그대로 나온다"는 문제를 아무도 눈치 못 챘다.

## 3. 스타일 4종 — 모서리와 여백

같은 테마라도 스타일이 바뀌면 인상이 꽤 달라진다. 스타일을 지정하지 않으면 테마마다 정해진 기본값을 쓴다.

| 스타일 | 모서리 | 여백 | 인상 | 쓸 곳 |
|---|---|---|---|---|
| `sharp` | 각짐 | 좁음 | 빽빽하고 격식 있음 | 데이터 많은 보고, 임원 보고 |
| `soft` | 살짝 둥글 | 보통 | 무난한 기업 문서 | 대부분의 경우 |
| `rounded` | 확실히 둥글 | 넉넉 | 친근함 | 마케팅, 캠페인 제안 |
| `pill` | 알약형 | 아주 넉넉 | 여백 많고 고급스러움 | 프리미엄 제안, 키노트 |

## 4. 페이지 카탈로그 15종

`얼굴`은 **같은 종류인데 생김새가 다른 판본** 수다. 얼굴이 1개면 그 종류의 슬라이드는 덱에서 몇 장이 나오든 전부 같은 모양이다.

### 4-1. 덱의 뼈대 (4종 · 얼굴 12개)

#### 표지 `cover` — 얼굴 3개
덱의 첫 장. **페이지 번호가 안 붙는다.**

| 얼굴 | 생김새 |
|---|---|
| `block` (기본) | 브랜드 대표색이 화면 전체. 우상단에 큰 반투명 원, 왼쪽에 44pt 흰 제목, 맨 아래 액센트 띠 |
| `split` | 좌 62% 밝은 배경 + 우 38% 색 패널 + 큰 원. **유일하게 밝은 표지**라 인상이 확 다르다 |
| `center` | 화면 전체 색, 48pt 제목을 정가운데. 가장 단순하고 강함 |

넣는 것: 제목(필수) · 부제 · 날짜 · 배지(예: 회사명, "제안서")

#### 목차 `toc` — 얼굴 3개

| 얼굴 | 생김새 | 한도 |
|---|---|---|
| `list` (기본) | 번호 + 항목 세로 나열. **7개 이상이면 자동 2열** | 없음 |
| `sidebar` | `list`와 같고 항목마다 왼쪽에 액센트 세로 막대 추가 | 없음 |
| `cards` | 카드 격자. 4개 이하는 1행, 5~8개는 2행. 카드마다 큰 번호 | **8개** |

넣는 것: 섹션 이름 목록 — 문자열, 또는 `{ label, desc }` 객체. **`desc`를 주면
세 얼굴 모두 항목 아래 한 줄 설명이 붙는 "설명형 오버뷰" 페이지가 된다** —
예전엔 이 페이지를 `layout` 손조판으로만 만들 수 있어서 모든 덱의 오버뷰가
같은 모양이었다.

> ⚠️ `list`와 `sidebar`는 사실상 같은 얼굴이다(막대 유무 차이). 실질 얼굴은 2개로 보는 게 정확하다.

#### 챕터 구분 `section` — 얼굴 3개
덱을 파트로 나누는 간지. 6장 넘는 덱에 이게 없으면 "그냥 나열"로 읽힌다.

| 얼굴 | 생김새 |
|---|---|
| `number` (기본) | 우측에 거대한 반투명 유령 숫자, 좌측에 큰 실제 숫자 + 제목 |
| `accentBlock` | 왼쪽 세로 색 띠 안에 숫자, 오른쪽에 제목 |
| `split` | 좌 42%가 통째로 색 패널, 그 안에 초대형 흰 숫자 |

넣는 것: 번호 · 제목(둘 다 필수) · 도입 한두 줄

#### 마무리 `summary` — 얼굴 3개

| 얼굴 | 생김새 | 한도 |
|---|---|---|
| `takeaways` (기본) | ✓ 체크 목록 + 하단에 큰 마무리 문장 | 5개 |
| `split` | 좌측 ✓ 목록 / 우측 "Next Steps" 카드(번호 원 + 항목) + 연락처 | 요점 5 · 다음단계 4 |
| `thanks` | 54pt 감사 문구 가운데, 아래 한 줄 요약과 연락처 | — |

넣는 것: 요점 목록(필수) · 제목 · 마무리 문장 · 다음 단계 · 연락처

### 4-2. 데이터 (4종 · 얼굴 11개)

#### 핵심 숫자 `stats` — 얼굴 2개
숫자 2~4개를 크게. **숫자를 불릿으로 나열하면 안 되는 이유**가 이 페이지다.

| 얼굴 | 생김새 |
|---|---|
| `cards` (기본) | 카드 안에 큰 값 + 라벨 + 보조설명 |
| `bare` | 카드 없이 훨씬 큰 값(60pt), 항목 사이에 얇은 구분선만 |

한도: **4개**. 넘으면 4개만 나오고 경고가 뜬다.

#### 차트 `chart` — 얼굴 3개 · 그래프 5종

| 얼굴 | 생김새 |
|---|---|
| `full` (기본) | 차트 전폭, 결론 한 줄이 아래 액센트 막대와 함께 |
| `split` | 좌 62% 차트 + 우 38% 카드에 20pt 결론 (결론 없으면 자동으로 `full`) |
| `banner` | 24pt 결론 선언문이 **위**, 차트가 아래 — 읽는 순서를 뒤집는다 |

그래프 5종:
| 그래프 | 쓸 곳 |
|---|---|
| `bar` | 항목별 크기 비교 |
| `line` · `area` | 시간에 따른 추이 |
| `pie` · `doughnut` | 전체 중 비중 (반드시 한 줄 결론을 같이) |

넣는 것: 그래프 종류 · 가로축 항목 · 데이터 계열(필수) · 제목 · **결론 한 줄** · 출처
- 결론을 넣으면 차트 아래에 액센트 막대 + 굵은 문장이 붙는다. 차트만 있는 장보다 훨씬 잘 읽힌다.
- 출처는 우하단에 작은 이탤릭.
- 범례는 계열이 2개 이상이거나 파이/도넛일 때만 나온다.

#### A vs B `compare` — 얼굴 3개

| 얼굴 | 생김새 |
|---|---|
| `cards` (기본) | 좌우 카드 두 개, 각각 제목 + 불릿 |
| `vs` | 카드 없이 맨 컬럼 두 개 + 가운데 액센트 레일 + "VS" 원형 칩 — 훨씬 가벼움 |
| `stacked` | 위/아래 밴드(before/after 읽기). 한쪽 불릿 3개 초과면 자동으로 `cards` |

#### 절차·일정 `timeline` — 얼굴 4개 · 한도 6단계

| 얼굴 | 생김새 |
|---|---|
| `rail` (기본) | 가로 레일 + 번호 원. 단계가 많으면 설명이 좁아짐 |
| `vertical` | 세로 배치 — 단계마다 설명이 전폭을 쓴다. **설명이 긴 일정에 최적** |
| `bars` | 균등 블록 + 큰 유령 숫자 — "단계" 느낌이 강한 로드맵용 |
| `chevron` | **화살표 체인** — 컨설팅 프로세스 스트립. 라벨은 화살표 안, 설명은 아래 |

### 4-3. 텍스트·기타 (5종 · 얼굴 12개)

| 종류 | 생김새 | 한도·특이사항 |
|---|---|---|
| `bullets` — 얼굴 4개 | `rows`(액센트 점) · `cards`(번호 타일, 4개는 2×2) · `numbered`(에디토리얼 숫자+구분선) · `twoCol`(2열). 9개 이상은 컴팩트 목록 폴백 — 잘리지 않음 | 권장 6개 |
| `text` — 얼굴 3개 | `rail`(액센트 막대+문단) · `panel`(제목 좌측, 본문 카드 우측) · `twoCol`(문단 경계에서 2열 분할) | 권장 80단어 |
| `quote` | 초대형 장식 따옴표 + 26pt 이탤릭 가운데 정렬 + 출처 | — |
| `image` | 제목 + 이미지(비율 유지) + 캡션 | 이미지 비율이 생김새를 좌우 |
| `table` — 얼굴 3개 | `grid`(줄 표) · `zebra`(무테 줄무늬) · `kv`(그리드 없는 키/값 2단 — 2열 표 전용, 명시 선택시만). 9행부터 글자 축소 | **15행.** 넘으면 "… N more rows" 안내행 + 경고 |

### 4-4. 자유 조판 `layout` — 얼굴 무제한

여기가 **진짜 자유로운 유일한 페이지**다. 화면을 12칼럼으로 나누고 블록을 왼쪽→오른쪽으로 흘려 배치한다. 줄이 차면 자동 줄바꿈.

블록마다 정할 수 있는 것: 폭(1~12칸) · 카드 배경 유무 · 세로 정렬 · 최소 높이 · 강제 줄바꿈.

쓸 수 있는 블록 **10종**:

| 블록 | 내용 |
|---|---|
| `heading` | 소제목 (3단계 크기) |
| `paragraph` | 문단 |
| `bullets` | 액센트 점 목록 |
| `stat` | 큰 숫자 + 라벨 + 보조설명 |
| `quote` | 인용 + 출처 |
| `chart` | 차트(5종 전부 가능) |
| `image` | 이미지 + 캡션 |
| `kv` | 항목–값 2열 표 |
| `icon` | 아이콘 타일(68종 마케팅 세트) + 라벨 + 보조설명 — 4칸 카드 3개면 아이콘 행 |
| `spacer` | 빈 칸 |

**자주 쓰는 배치**
- 2단 구성 → 6칸 + 6칸
- 숫자 3개 한 줄 → 4칸 카드 3개
- 차트 + 옆에 해설 → 8칸 차트 + 4칸 카드
- 글 + 옆에 요점 → 7칸 문단 + 5칸 카드 불릿

**언제 쓰나**: 고정 페이지 어느 것도 안 맞을 때, 한 장에 숫자·차트·글을 섞어야 할 때, 덱이 단조로워질 때.

### 4-5. 레거시

`title` — 옛 표지. 지금은 `cover`의 `block` 얼굴과 똑같이 그려진다. **새로 쓰지 말 것.** 예전 데이터 호환용으로만 남아 있다.

## 5. 용량 한도 한눈에

한도를 넘긴 내용은 **조용히 사라지지 않는다.** 잘린 개수가 경고로 나오고, 표는 슬라이드 안에 "몇 행이 더 있다"는 안내행이 붙는다.

| 페이지 | 한도 | 넘으면 |
|---|---|---|
| `stats` 항목 | 4 | 4개만 표시 + 경고 |
| `timeline` 단계 | 6 | 6개만 표시 + 경고 |
| `summary` 요점 | 5 | 5개만 표시 + 경고 |
| `summary` 다음 단계 | 4 | 4개만 표시 |
| `toc` 카드 얼굴 | 8 | 8개만 표시 + 경고 (`list`는 한도 없음) |
| `table` 행 | 15 | 15행 + 안내행 + 경고 |
| `bullets` | — | 9개부터 형태만 바뀜, 잘리지 않음 |

글자가 상자에 안 들어가면 **자동으로 폰트를 줄여서** 맞춘다(최대 40%까지). 15% 미만의 축소는 정상 조판으로 보고 사용자 화면에서는 접어둔다.

## 6. 현재 만들 수 있는 것 / 없는 것

**된다**
- 위 15종을 자유롭게 조합한 임의 길이 덱
- 7 × 4 = 28가지 스킨 + 브랜드 색 파생 팔레트 어느 것이든
- 다크 덱 (`night` 테마)
- 발표자 노트 (모든 페이지)
- 남의 .pptx를 읽어 **우리 디자인으로 다시 그리기** (픽셀 복사가 아니라 내용 재조판)
- 남의 .pptx를 **원본 디자인 그대로** 고치기 — 문구 교체, 노트 수정, 슬라이드 복제·삭제·순서 변경. 마스터·테마·미디어는 그대로 남는다
- .potx 템플릿을 .pptx로 채워서 내보내기
- 만들어진 덱에서 **한 장만 골라 고치기**
- 미리보기 화면과 실제 .pptx 파일이 **같은 계산에서 나온다** — 미리보기와 결과물이 다를 수 없다
- **AI가 자기 덱을 눈으로 확인한다** — 만든 직후 전 슬라이드 이미지를 받아 넘침·겹침·단조로움을 스스로 고친다 (덱당 1회)
- 내보낸 파일을 즉시 되읽어 **내용 생존을 검증**한다 — 깨진 파일이 "저장됨"으로 보고되는 일이 없다

**안 된다 (아직)**
- 고객 로고 자동 삽입
- `night` 외의 다크 **프리셋** (브랜드 색 + night 조합으로 다크 브랜드 덱은 가능)
- 폰트 직접 지정 (테마에 묶여 있음)
- 애니메이션 · 전환 효과 새로 넣기 (원본 보존 편집에서는 기존 것이 유지된다)
- 도형 직접 그리기 (삼각형·화살표 등 — 사용 가능한 도형은 사각형·둥근사각형·원뿐)
- 원본 보존 편집의 **화면 미리보기** — 남의 디자인은 우리 렌더러가 못 그려서, 편집 결과는 텍스트 개요로 확인한다

## 7. 해소된 한계와 남은 한계

이 문서 초판(2026-08-14)이 지적한 약점 5개는 **전부 해소됐다**:

| 초판의 약점 | 해소 |
|---|---|
| ① 트래픽 많은 페이지가 얼굴 1개 | 차트·불릿·비교·표·타임라인·본문에 얼굴 15개 추가 (22 → 37) |
| ② 자동 얼굴 교체가 안 돎 | 덱 제목 기반 자동 배정 — 첫 등장부터 변하고, 덱마다 다르고, 수정 중엔 안 바뀜 |
| ③ 단조로움 검사가 종류 수를 셈 | **생김새 단위**로 교체 — 같은 얼굴 3연속·생김새 가짓수 부족을 잡는다 |
| ④ 자유 조판을 아무도 안 씀 | 단조로운 덱에 시스템이 직접 `layout` 사용을 권고 + 아이콘 68종 추가 |
| ⑤ 시스템이 덱의 목적을 모름 | 목적 6종 페이지 구성표 — 목적별로 빠진 장·순서 문제를 지적 |

**남은 한계** (지금 시점의 솔직한 목록):
- 원본 보존 편집(남의 덱 고치기)은 **화면 미리보기가 없다** — 텍스트 개요로 확인
- 로고 자동 삽입 없음 · 폰트 직접 지정 없음 · 애니메이션 신규 생성 없음
- `night` 외 다크 프리셋 없음 (단, `night` + 브랜드 색 조합으로 다크 브랜드 덱은 가능)
- 도형은 사각·둥근사각·원 + 아이콘 68종 (임의 도형·화살표 없음)

## 8. 관리 가이드 — 무엇을 바꾸려면 얼마가 드나

| 바꾸고 싶은 것 | 난이도 | 영향 범위 | 확인해야 할 것 |
|---|---|---|---|
| 테마 색 하나 · 글꼴 교체 | **낮음** | 그 테마로 만든 **모든 덱** | 어두운 배경 대비, 화면 눈검사 |
| 테마 **추가** | **낮음** | 없음(추가만) | 안내 문서 6곳에 이름 추가 |
| 여백·모서리 조정 | **낮음** | 그 스타일을 쓴 모든 덱 | 전 페이지 눈검사 |
| 용량 한도 변경 | **낮음** | 해당 페이지 전부 | 넘칠 때 경고가 제대로 나오는지 |
| 기존 페이지 **모양 수정** | **중간** | 그 종류 슬라이드 **전부** + 기준 스냅샷 재기록 | 스냅샷 차이를 한 줄씩 리뷰 |
| 얼굴(variant) **추가** | **중간** | 없음(추가만) | 내용이 안 잘리는지, 다크에서도 읽히는지 |
| 페이지 **종류 추가** | **높음** | 계약·미리보기·내보내기·안내문서 전부 | 아래 계약 4개 전부 |

### 절대 어겨선 안 되는 계약 4가지

이건 취향 문제가 아니라 **전부 실제 사고가 났던 지점**이다.

1. **미리보기와 파일은 같은 계산에서 나와야 한다.** 어느 한쪽에만 코드를 추가하면 "화면과 다르게 나온다"는 신고가 들어온다.
2. **내용은 조용히 버려지지 않는다.** 담을 수 없으면 경고를 내거나 다른 얼굴로 물러선다. 말없이 6개 중 4개만 그리는 건 금지.
3. **모르는 이름은 즉시 에러.** 없는 테마·스타일·페이지 종류가 오면 바로 실패한다. 기본값으로 조용히 떨어지면 아무도 문제를 모른다.
4. **색은 역할로만 쓴다.** "다크 테마면 흰색" 같은 분기를 페이지마다 새로 적으면 안 된다. 색 역할표 한 곳에서만 결정한다.

## 9. 세일즈·CS용 짧은 답변

**"어떤 디자인 있어요?"**
> 7가지 테마(+브랜드 색 파생)와 4가지 분위기로 스킨을 잡고, 15종 페이지 형식 × 38가지 레이아웃을 목적(제안·보고·의사결정·정렬·분석·교육)에 맞는 구성표대로 조합합니다. 같은 요청이라도 덱마다 레이아웃이 자동으로 달라집니다.

**"우리 브랜드 색으로 맞출 수 있나요?"**
> 됩니다. 브랜드 색 하나만 주시면 배경·본문·카드·차트 색까지 전체 팔레트가 그 색에서 파생되고, 글자가 안 읽히는 조합은 자동으로 보정됩니다.

**"로고 넣을 수 있나요?"**
> 이미지 페이지로는 가능하지만 모든 장에 자동으로 박히는 로고 기능은 아직 없습니다.

**"기존 PPT를 우리 디자인으로 바꿔주나요?"**
> 됩니다. .pptx를 올리면 내용을 읽어 Twixy 디자인으로 다시 조판합니다. 픽셀 복사가 아니라 새로 그리는 방식이라 원본의 도형·애니메이션은 넘어오지 않고 텍스트와 표 위주로 옮겨집니다.

**"만든 다음에 수정 되나요?"**
> 슬라이드를 골라 "이 장만 차트로 바꿔줘" 식으로 한 장씩 고칠 수 있고, 나머지 장은 그대로 유지됩니다.

**"슬라이드 몇 장까지 되나요?"**
> 장수 제한은 없습니다. 다만 한 장에 들어가는 양에는 한도가 있어(숫자 4개, 표 15행, 타임라인 6단계 등) 넘으면 잘린 사실을 알려줍니다.
