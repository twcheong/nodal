> **대상:** Twixy 팀 (개발)
> **한 줄:** 3·4차가 "같은 프롬프트로 만든 두 파일을 X-ray해서 레버를 뽑는" 루프였다면, 여기서부터는 **유저가 실제로 만든 덱의 스크린샷과 로그**가 레버를 정했다. 매 차수가 "이 페이지 이상하다" 한 장에서 출발해 그 증상의 코드 근원까지 내려간 기록.

## 1. 이번 차수의 방법 — 증상 한 장 → 코드 근원

3·4차는 파일 두 개를 나란히 놓고 수치를 비교했다. 5차부터는 입력이 달라졌다: 유저가 실사용 덱의 **스크린샷 한 장**이나 **QA 로그 한 덩어리**를 던지고, 거기서 근원을 역추적했다. 이 방식이 잡아낸 것들은 벤치마크 비교로는 안 나왔을 종류다 — 비교는 "무엇이 부족한가"를 알려주지만, 실물은 "무엇이 **틀렸는가**"를 알려준다.

일곱 번 중 **네 번이 우리 코드가 스스로 만든 문제**였다:

| 증상 | 근원 | 차수 |
|---|---|---|
| 페이지 아래가 통째로 빔 | 페인터가 밴드 대신 하드코딩 y/height를 씀 | 5 |
| 한글이 단어 중간에서 쪼개짐 | autofit이 **높이만** 검사 | 6 |
| 디바이더가 안 지워짐 | `deck-patch`에 **삭제 연산이 없음** | 7 |
| 프리뷰가 안 뜸 | 슬라이드 필수 필드에 이름 검증이 없음 | 9 |

나머지 셋은 벤치마크 규범과의 격차(§8·§11)와 모델 한계(§10)였다.

## 2. 5차 — 콘텐츠 밴드 (76430a2)

**증상:** "페이지에 빈 공간이 너무 많아."

**측정:** 슬라이드별 콘텐츠 하단 좌표를 재니 유저 체감이 그대로 숫자로 나왔다.

| 덱 | 평균 하단 여백 |
|---|---|
| Twixy 고도화3 | **1.94"** (7.5" 중 26%) |
| 벤치마크 | **0.12"** — 전 장이 7.36"까지 채움 |

**근원:** `grid.ts`(`layout` kind)만 `CONTENT_TOP ~ PAGE_H-BADGE_RESERVE` 밴드를 계산해 채우고 있었다. 고정 kind 페인터들은 저마다 y(1.45/1.5/1.55/1.6)와 높이(5.3/5.4/5.5)를 하드코딩한 채 **행 높이에 상한만 걸고 꼭대기는 고정**했다 — `Math.min(0.9, 5.5/n)`. 항목이 적을수록 아래가 비는 구조였다(불릿 3개 = 5.5" 중 2.7"만 사용).

**수정:** `common.ts`에 `contentBand()` / `rowBand()` 신설. 밴드 정의는 하나, 남는 여백은 위아래로 나눠 스택을 **균형** 배치. 전 페인터 적용 — bullets 5면 · toc 3면 · stats 2면 · compare 3면 · timeline 4면 · summary · chart 3면.

**표는 별건이었다:** pptxgenjs가 행 높이를 자체 계산해 4행 표가 ~1"로 찍히고 5"가 비었으며, SVG 프리뷰는 행을 0.34"로 캡해 **두 페인터가 서로 다른 기하**를 그리고 있었다. `El.table`에 `rowH`를 추가해 레이아웃 코어가 행 높이를 소유하도록 통일(`<a:tr h="0.62">` 반영 실측).

**결과:** 1.94" → **1.01"**.

**부수:** Content 모드 양옆 패널이 모드 진입 즉시 열려 입력 전부터 채팅을 밀던 것 → 다른 모드(`displayWorkflow` 대기)와 같은 규칙으로 첫 답변 이후 열리게.

## 3. 6차 — maxLines (e1b77f8)

**증상:** 스탯 라벨이 `@edis_agency_ 팔로 / 워`로 쪼개짐. 유저 질문이 핵심을 찔렀다 — *"이거 만들고 스샷 찍어서 검증하는 방식으로 잡혔어야 하는 거 아님?"*

**근원 두 겹:**

1. **autofit이 높이만 본다.** 15pt 2줄이 0.50"로 0.50" 박스에 '맞아서' `overflowIn=0` → 축소도 경고도 없었다. 한글은 글자 사이가 합법 개행점이라 짧은 라벨도 단어 중간에서 끊긴다.
2. **시각 QA가 원리적으로 못 본다.** 컨택트시트는 슬라이드 1장이 **290×163px**, 15pt 라벨이 **4.5px**다. 벤치마크는 `pdftoppm -r 150`으로 슬라이드당 1950×1097px를 만들어 **전부** 검사한다 — 면적 45배 차이. 열을 줄여도 openclaw가 이미지를 1200px로 캡해 더 나빠진다.

**수정:** `TextStyle.maxLines` 추가, autofit의 `fits()`가 높이 **AND 줄 수**를 함께 검사. 설계상 한 줄인 텍스트에 `maxLines: 1` 적용 — stats 라벨/서브라벨, timeline 라벨(4면), icon 라벨, step 제목, chips, funnel 라벨, kv 양쪽, toc 설명형 라벨, 커버 칩. 문단류는 그대로.

실측: 실패했던 4개 라벨이 15 → 15/14.5/14.5/12pt로 **전부 1줄**.

**결론이 §8의 기하 검사로 이어진다:** 타이포는 코드가 잡아야 하는 클래스다. 시트는 코드가 못 보는 것(색 인상, 의미적 어색함)에만 쓴다.

## 4. 7차 — 디바이더와 삭제 연산 (7e33ac7)

**증상:** *"분명 섹션 제목 페이지 지우라고 했는데 여전히 있네?"* — 세 번째 요청이었다.

**로그 포렌식:** QA 라운드에서 모델은 **정확히 판단했다** — "슬라이드 3, 6, 9는 bare divider이므로 삭제하고 제목에 합칩니다." 그런데 실물을 열어보니 디바이더는 그대로였고 s5/s6·s7/s8이 **중복**이었다.

**근원:** `applyPatch`가 `slides[index] = slide` — **교체만 되고 삭제가 없다.** 모델은 "뒤 슬라이드를 앞으로 당겨 덮어쓰기"로 삭제를 흉내냈고, 지시는 도달했으나 실행 수단이 없었다.

**수정 ①: 삭제 연산.** `{ "index": N, "delete": true }`. 한 답장의 패치는 전부 **원본 인덱스 기준 일괄 적용**(`applyPatches`) — 순차 적용은 삭제가 섞이는 순간 뒤 패치의 인덱스를 밀어버린다. 모델은 한 화면(원본)을 보고 말하므로 계약도 스냅샷 기준이어야 한다.

**수정 ②: `section`을 어휘에서 제거.** `LEGACY_KINDS`(title·section)는 페인터는 유지하되 프롬프트가 가르치지 않는다 — **모르는 kind는 만들 수 없다.** purpose 표의 `part` 슬롯 전부 삭제, 생성기/체커가 legacy를 건너뛴다.

> 왜 여기까지 갔나: 프롬프트 강도로 두 번 실패했다. "없애라" → 내가 임의로 붙인 **"14장 이상이면 허용"** 예외 → 17장 덱에서 5장 재등장(모델은 내 규칙을 정확히 지킨 것). 스펙을 약화시킨 쪽이 원인이었다.

**부수:** 그리드가 남는 세로 공간을 전부 아래에 쌓던 것(주석에 *"reads as intentional whitespace"*라고 적혀 있었다 — 희망사항) → 행 비례 확대 + 내부 센터링, 아이콘은 높이 인지(0.6→1.3"). compare `vs`의 제목 밑 액센트 밑줄 삭제, 레일·VS 칩을 밴드가 아니라 **실제 콘텐츠 높이** 기준으로.

## 6. 기하 검사 — 눈이 아니라 산술 (`layout/geometry.ts`)

규범이 "눈으로 보라"는 항목은 우리에겐 산술이다. 그들이 봐야 하는 이유는 **display list가 없어서**고, 우리는 `El[]`에 inch 단위 rect를 전부 갖고 있다.

**검사 3종** (정밀도 우선 — 오탐은 모델이 학습해서 무시하게 만든다):
1. 불투명 **텍스트끼리 겹침**
2. 잉크가 **페이지 밖**
3. **0.3" 가장자리 거터** 침범

**정밀도를 만든 두 결정:**
- 박스가 아니라 **잉크**(래퍼의 실제 줄 폭·`blockH`·`valign`)로 잰다 — 가운데정렬 라벨의 넓은 박스가 가장자리에 닿는 건 오탐이고, 이걸 고치라고 보고하면 모델이 멀쩡한 슬라이드를 망친다.
- 반대로 **자기 shape을 가진 요소(칩)는 박스가 발자국**이다 — 이 구분이 없었으면 VS 칩 충돌을 놓쳤다.
- 고스트 타입(`transparency`)은 제외 — 그 위에 글자를 얹으라고 만든 것이다.

**첫 실행에서 실제 결함 2건 적발:** VS 칩이 우측 열 제목을 0.14" 덮고 있었고, chart `Source:` 줄이 하단 0.23"에 있었다. 둘 다 수정. 현재 전 픽스처 노트 **0**, 인위적 결함 3종은 전부 적발.

## 7. 9차 — 슬라이드 필수 필드 계약 (ccbf2fc)

**증상:** "ppt 미리보기 자체가 안 나오는 중" + 로그.

**근원:** `summary`에 `variant:'split'`과 `nextSteps`만 있고 필수 필드 `takeaways`가 없어 페인터가 `Cannot read properties of undefined (reading 'length')`로 죽었다. 앱의 커밋-전 검증은 제대로 동작해 기존 덱을 지키고 모델에게 재시도도 보냈지만 — **에러가 '어느 필드'인지 말하지 못했다.**

이건 `assertBlockBody`가 이미 푼 문제의 **한 층 위**다: layout 블록 바디는 이름으로 검증하는데 슬라이드 필드는 아무도 안 봤다. `SLIDE_FIELDS`가 처음부터 계약이었으니 그 표로 강제한다(`assertSlideFields`) — 새 필수 필드는 선언되는 즉시 강제되고 유지할 두 번째 목록이 안 생긴다.

```
slide 15 (summary): 'summary' is missing required field `takeaways`.
Required: takeaways · optional: title, closing, nextSteps, contact, variant
```

**하네스가 내 버그를 즉시 잡았다:** 컬렉션 타입 검사를 `sig.includes('[]')`로 했더니 `compare.left`의 `{ title, bullets: string[] }`가 배열로 오판돼 픽스처의 compare 슬라이드가 전부 걸렸다 → 시그니처의 '모양'(`endsWith('[]')` 또는 `[…]`)으로 판정하도록 수정.

## 8. 10차 — 덱 언어 교정 (e58159c)

**증상:** 한국어 덱에 `兄弟` / `stratégiques` / `engajament` / `제품 계정へ`.

**근원:** 채팅에는 이미 post-turn 교정기(`correct-language`, 서브모델 flash-lite 1회)가 있는데 덱은 못 고친다 — 그 시스템 프롬프트가 *"Preserve … **code blocks** … exactly as-is"*이고 **`deck-spec`이 곧 코드블록**이라 교정 대상에서 정확히 제외돼 있었다. 프롬프트로는 못 푸는 모델 한계라 서브모델로 내린다(유저 지시).

**설계 — 모델이 JSON을 아예 보지 않는다:** 원 JSON을 맡기면 파싱 불가한 응답 한 번에 덱이 죽는다.

- `shared/deck/strings.ts` — 스펙의 **프로즈 문자열만** 순회 순서대로 뽑고 같은 순회로 되꽂는다(collect/apply가 한 walk을 공유해 어긋날 수 없음). `kind`/`variant`/`type`/`chartType`/`imagePath`/`theme`/`style`/`purpose`는 기계값이라 제외. `name`은 **chart series면 프로즈, icon 블록이면 로스터 id**라 문맥으로 가른다. 길이 불일치는 통째로 폐기 — 밀린 배열을 되꽂으면 덱이 뒤섞인다.
- `electron`: `subModelChat()`으로 키/모델/에러 처리를 한 곳에 모으고(기존 핸들러도 사용) `correct-language-batch` 추가. 응답은 펜스 제거 → JSON 파싱 → 전원 문자열 → 길이 일치를 **모두** 통과해야 채택.
- `CopilotView`: 덱 커밋 **뒤에** 실행(프리뷰는 즉시, 교정은 왕복 필요 — 채팅이 메시지 먼저 붙이고 나중에 patch하는 것과 같은 패턴). 교정본도 `buildDeck`으로 검증하고, 그 사이 다음 턴이 돌았으면 덮어쓰지 않는다. 기존 `twixy-lang-correction` 플래그 존중.

## 9. 11차 — 페이지 타입과 팔레트 (fe86f4b)

벤치마크의 **"For Each Slide"** 섹션이 페이지 타입 카탈로그다. 넷 중 셋만 갖고 있었다.

| 규범의 Layout option | 우리 |
|---|---|
| Two-column | ✓ `layout` span-7+5 |
| **Icon + text rows** | ❌ → `step` 바디에 `icon?` (번호 칩 자리에 아이콘, 행 기하 재사용) |
| 2×2 / 2×3 grid | ✓ |
| **Half-bleed image** | ❌ → `image` `variant:'bleed'` (사진이 한쪽을 가장자리까지, 반대쪽이 제목+캡션) |

**팔레트 3종 추가** — 우리 7종이 닿지 않던 도메인: `terra`(공예·F&B·헤리티지) · `berry`(호스피탈리티·뷰티) · `slate`(중립 임원용, 클라이언트 brand hex와 안 싸움). 전 롤 대비 실측 결과 본문 롤은 **10/10 테마 4.5:1 통과**. terra는 첫 조합에서 칩 대비 1.98(액센트가 세이지)이라 후보를 실측해 `B85042`로 교체 → 4.92, 기존 7종(2.84–3.95)보다 낫다.

**부수:** `bullets 'cards'` 본문을 카드 안에서 세로 중앙 정렬 — 카드가 밴드를 채우게 된 뒤 한 줄 항목이 카드 위에 붙고 아래 2"가 비었다.
