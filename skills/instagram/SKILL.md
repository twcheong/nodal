# Instagram Post Collection

Collect a profile's posts with CORRECT upload-type detection (reel / carousel / photo), plus caption and exact post date. Covers the Reels-tab posts the Posts grid never shows. Read this before any Instagram post-collection or audit node.

## Purpose

Three things the profile grid alone cannot give you. (1) Upload type — URL cannot separate carousel from photo, both use /p/; read the tile's img.alt. (2) The full post list — some reels live only in the Reels tab, so a short count means look there, not that posts were deleted. (3) Caption and date — these exist ONLY on the post's own page, so every post must be opened; read the date from <time datetime> and never re-derive it, and never leave a caption cell blank, because a blank cannot be told apart from a post that was never read.

**KPI:** posts_collected_complete

**Platforms:** Instagram

## Triggers

Activates when the user requests this skill directly.

## Behavior

### 1. Collect Data — Detect upload type from the profile grid

- Open **Instagram** browser session
- 🚨 "Twixy" is THIS APP'S NAME — NOT an Instagram username. NEVER go to instagram.com/twixy.
- 🚨 You are a sub-agent. Run all browser calls yourself. Do NOT spawn further sub-agents.
- Always use the run's assigned profile for browser calls.
- browser status running:false does NOT mean not logged in — cookies persist in the profile.
- ── WHY URL IS NOT ENOUGH ──────────────────────────────────────────────
- Instagram post URLs give you only PART of the type:
- • /reel/<id>/  → reel        (reliable from URL)
- • /p/<id>/     → carousel OR photo   (URL CANNOT tell which)
- Carousels (multi-image posts) and single photos BOTH use /p/. Classifying
- every /p/ as "photo" silently drops all carousels — the exact bug this skill
- exists to prevent.
- ── THE SIGNAL: grid tile image alt text ───────────────────────────────
- On a profile grid, a carousel tile's <img> carries alt text containing the
- word "Carousel" (Instagram writes e.g. alt="Photo by … on … . May be a
- Carousel of N images."). A single photo's alt does NOT contain "Carousel".
- This is in the DOM `img.alt` — it is NOT reliably in the accessibility tree,
- so a snapshot/aria read will miss it. You MUST use `evaluate`, not a snapshot.
- ── PROCEDURE ──────────────────────────────────────────────────────────
- Step 1: Open the profile grid, wait for it to render (browser act kind=wait
- timeMs=5000). Scroll to load all posts if collecting the full grid.
- Step 2: Run ONE evaluate that reads each post anchor + its image alt, and
- classifies in this order — reel (URL) → carousel (alt) → photo:
- browser act kind=evaluate fn='() => { const seen = new Set(); const out = []; for (const a of document.querySelectorAll("main a[href*=\"/p/\"], main a[href*=\"/reel/\"]")) { const m = a.href.match(/instagram\.com\/(p|reel)\/([A-Za-z0-9_-]+)\//); if (!m || seen.has(m[2])) continue; seen.add(m[2]); let type = m[1] === "reel" ? "reel" : "photo"; if (m[1] === "p") { for (const img of a.querySelectorAll("img")) { if ((img.alt || "").includes("Carousel")) { type = "carousel"; break; } } } out.push({ position: out.length + 1, url: "https://www.instagram.com/" + m[1] + "/" + m[2] + "/", upload_type: type }); } return JSON.stringify(out); }'
- Step 3: The returned upload_type is authoritative for reel vs carousel vs
- photo. Carry it through the rest of collection — do NOT re-derive
- type from the URL later (that re-introduces the bug).
- ── FALLBACK (only if grid alt is missing for some tiles) ──────────────
- If a tile's images have no alt yet (lazy-loaded), scroll it into view and
- re-run the evaluate. If still ambiguous, open that single post and check:
- • a "Next" arrow (aria-label="Next") or slide pagination dots present → carousel
- • none of those, single image → photo
- Opening posts is the EXPENSIVE path — only for the few tiles the grid could
- not resolve, never as the default.

### 2. Collect Data — Find the reels the Posts grid never shows

- ── WHY THE GRID IS NOT THE WHOLE ACCOUNT ──────────────────────────────
- A profile's Posts grid does NOT always contain every reel. Some reels appear
- ONLY under the Reels tab (/reels/). If you collect from the grid alone and the
- account's stated post count is higher than what you found, the difference is
- almost always these reels — not deleted posts.
- Measured (bsm.canada, 2026-08-13): the grid yielded 56, the account showed 60.
- The 4 were reels living only in the Reels tab. A run that "explains" such a gap
- as deleted/unavailable posts is wrong and will ship short every time.
- ── PROCEDURE ──────────────────────────────────────────────────────────
- Step 1: Collect the Posts grid first (previous COLLECT block).
- Step 2: If the count is short of the target, open <profile>/reels/ and run the
- SAME anchor-scan there. Everything found is upload_type = reel.
- Step 3: Union the two sets on the post id (the /p/<id>/ or /reel/<id>/ part).
- The Reels tab repeats reels already in the grid — dedupe, do not append.
- 🚨 A Reels-tab tile carries a thumbnail and a view count and NOTHING ELSE.
- No caption, no date. Every reel found this way MUST go through the caption
- and date step below, or it lands in the export as an empty row.

### 3. Collect Data — Read caption and exact date from each post page

- ── WHY YOU MUST OPEN THE POST ─────────────────────────────────────────
- Neither the Posts grid nor the Reels tab carries a caption. The grid tile's
- img.alt sometimes contains a date, but it is a rendered label, not the post's
- timestamp, and it is absent on video tiles. Caption and true timestamp exist
- only on the post's own page.
- ── NEVER RE-DERIVE THE DATE ───────────────────────────────────────────
- Do NOT compute a date from a relative label ("6w", "May 4") or from your own
- sense of what today is. Measured failure (2026-08-13): an entire 56-row
- inventory came back shifted by a CONSTANT −69 days because dates were
- re-derived against a wrong "today" instead of read from the DOM. A uniform
- offset across every row is the signature of this bug.
- If the source data already has an ISO timestamp, carry it through untouched.
- Re-collect a date only for posts that do not have one yet.
- ── THE SIGNAL: <time datetime> ────────────────────────────────────────
- The post page renders <time datetime="2026-05-04T12:28:15.000Z">. Comment
- timestamps use the same tag, so take the EARLIEST one: a comment cannot
- predate the post it is on. That rule survives Instagram's class-name churn,
- which a positional selector does not.
- ── PROCEDURE (per post URL) ───────────────────────────────────────────
- Step 1: Navigate to the post URL. browser act kind=wait timeMs=3000.
- Step 2: One evaluate reads timestamp + caption together:
- browser act kind=evaluate fn='() => { const ts = [...document.querySelectorAll(\"time[datetime]\")].map(e => e.getAttribute(\"datetime\")).filter(Boolean).sort(); const posted = ts[0] || null; let cap = \"\"; const h1 = document.querySelector(\"h1\"); if (h1 && h1.innerText) cap = h1.innerText.trim(); if (!cap) { const og = [...document.querySelectorAll(\"meta\")].find(m => m.getAttribute(\"property\") === \"og:description\"); const c = og && og.getAttribute(\"content\"); const i = c ? c.indexOf(\": \") : -1; if (i > -1) cap = c.slice(i + 2).replace(/^[\"\\u201C]|[\"\\u201D]$/g, \"\").trim(); } return JSON.stringify({ url: location.href.split(\"?\")[0], posted_at: posted, caption: cap || null, status: cap ? \"ok\" : (posted ? \"no-caption\" : \"not-loaded\") }); }'
- Step 3: Read `status` and act on it — this is the whole point of the step:
- • ok          → write the row
- • no-caption  → the page loaded and the post genuinely has none. Write the
- literal string "(no caption)", NOT an empty cell.
- • not-loaded  → nothing rendered. Wait longer and retry ONCE. If it still
- fails, write "(not loaded)" and report that URL as failed.
- 🚨 NEVER write an empty caption cell. A blank means two different things —
- "this post has no caption" and "we never managed to read it" — and the
- reader cannot tell them apart. The whole reason this rule exists is that
- blanks get read downstream as "the data ends here" and get re-collected
- forever. Spend one string to make the two cases distinguishable.
- Step 4: Append the row to the output file IMMEDIATELY after each post, then
- move on. Do not hold pages in context and write at the end — that is
- what made an earlier run carry 6.6M input tokens on one node.

### 4. Track Results — Report classification and completeness

- Report each post as: position, url, upload_type (reel | carousel | photo),
- posted_at (ISO), caption.
- Self-checks — run these before declaring the node done:
- • The count of carousels should be > 0 for most real business accounts — if
- every /p/ came back "photo", the alt-text check did not run; re-do Step 2.
- • Collected count vs. the target count. If short, you have NOT finished —
- check the Reels tab before concluding anything is missing or deleted.
- • Rows with an EMPTY caption cell must be 0. "(no caption)" is fine; blank is
- a bug in this node, not a property of the account.
- • Rows with a missing posted_at must be 0 for posts that were opened.
- • If every date lands the same distance from the source dates, you re-derived
- them instead of reading <time datetime> — go back and read the DOM.
- Report the failures explicitly: "N posts collected, M captions unreadable
- (list URLs)". Never report a count as complete while rows are blank.
