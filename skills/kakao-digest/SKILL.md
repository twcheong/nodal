# Kakao Digest

Reads the recent KakaoTalk conversation captured on screen (via tool-read-kakao's logbook OCR) and turns it into an actionable digest: groups the lines into customer inquiries, orders, complaints/issues, and small talk, summarizes each group, and drafts optional reply suggestions. Composition only — no new tools: tool-read-kakao for the source, an LLM sub-agent for classification + summary. OCR text is approximate, so the skill flags low-confidence lines rather than inventing content. The user supplies how far back to read (minutes) and optionally which category to focus on; the skill returns the categorized digest in chat and optionally saves it. Trigger phrases: 카톡 정리, 카톡 요약, 카카오 문의 정리, 고객 문의 요약, kakao digest, summarize kakao, 카톡 이슈 정리.

## Purpose

Read the recent KakaoTalk conversation, classify each meaningful line into inquiry / order / issue / other, summarize each bucket, and surface reply-worthy items — without fabricating text the OCR did not capture.

**KPI:** kakao_digests_shipped

## Triggers

Activates when the user requests this skill directly.

## Behavior

### 1. Collect Data — Pull recent kakao lines via OCR

- - Resolve scope from the user's request:
- sinceMinutes: how far back to read. Default 60.
- limit: max OCR lines. Default 50.
- focus: optional single category to emphasize (inquiry / order / issue). Default: all.
- - Call tool-read-kakao with { sinceMinutes, limit }. Store the returned lines as $kakao_lines.
- - If lines is empty, tell the user no recent kakao capture was found (logbook may be off) and stop — do NOT fabricate a conversation.

### 2. Analyze — Categorize and summarize the conversation

- Spawn **kakao_classifier**:
  - Task: "Classify each meaningful line from this OCR'd KakaoTalk transcript into one of: inquiry (customer question), order (purchase/booking intent), issue (complaint/problem), other (small talk/noise). OCR text is approximate — when a line is garbled or ambiguous, mark it low_confidence:true rather than guessing its meaning. Then for each non-empty category write a 1-3 bullet summary, and for inquiries/issues flag which items need a human reply. Return { buckets: { inquiry:[], order:[], issue:[], other:[] }, summary_by_bucket: {...}, reply_needed:[...], headline: 'one line' }. Do not invent content not present in the lines."
  - Input: `$kakao_lines`
  - Output: `$digest`

### 3. Track Results — Present digest and optionally save

- - Present the digest in chat: lead with the headline, then per category (inquiry / order / issue) show the summary bullets and the reply-needed items. Skip empty categories. Mark low-confidence lines clearly.
- - If the user asked to save/keep/파일로: call the write tool to persist a markdown digest at "`~/.openclaw/workspace/twixy/data/insights/`/kakao_digest_{date}.md", then report the relative path (e.g. data/insights/kakao_digest_2026-07-06.md).
- - If the user did not ask to save, return the digest in chat only.
- Emit signal `kakao_digest_ready`
- WITH payload = { headline: $digest.headline, reply_needed: $digest.reply_needed }
- TO SKILL "Watchtower"
