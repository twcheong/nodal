# PPTX Deck Builder

Build a polished PPTX deck: outline → themed build → QA pass. Read this before any slide / deck / PPT node.

## Purpose

Every deck ships with a cover, a table of contents, varied slide kinds, a theme that fits the topic, speaker notes on every slide, and passes a 3-axis QA (Content / Design / Coherence) before the node completes. A deck of 10 bullet slides in a row is the failure this skill exists to prevent.

**KPI:** deck_qa_passed

## Triggers

Activates when the user requests this skill directly.

## Behavior

### 1. Analyze — Outline before you build

- 🚨 Do NOT call tool_write_pptx until the outline below exists. Slides written one-by-one without an outline drift, repeat layouts, and lose the storyline.
- 🚨 tool_write_pptx writes the WHOLE deck in ONE call. Never shell out to python-pptx / pandoc — no Python in this runtime.
- ── STEP 1: PURPOSE — pick the id, set payload.purpose ──────────────────
- What must this deck MAKE HAPPEN? Choose from the table below and pass the id as payload.purpose. The tool checks the deck against that purpose's page table and returns what is missing in `structure` — declare it, do not guess around it.
- ── PURPOSES: pick one, follow its page table (generated — do not hand-edit) ─
- pitch — make them choose us. Audience: external prospect. Success: a next meeting or a signed contract. Budget: ~10 slides.
- open (x1, cover) — the promise: who we are and what changes for them
- stakes (x1, stats / chart / quote / text) — their problem in THEIR numbers — before any word about us
- agenda (optional, toc) — the route, only if the deck runs past 8 pages
- diagnosis (x1-2, bullets / table / chart / layout) — what is actually broken today, named specifically
- approach (x1-2, timeline / layout / bullets / compare) — what we would do, in the order we would do it
- proof (x1-2, stats / compare / image / quote / table) — evidence we have done this — a result, not an adjective
- offer (optional, table / layout / compare) — scope, timeline, price — concrete enough to say yes to
- ask (x1, summary) — the single next step, with a date — variant split + nextSteps
- report — tell them accurately what happened. Audience: client or manager. Success: trust, and one shared picture of status. Budget: ~12 slides.
- open (x1, cover) — period and scope in the title — no suspense
- agenda (optional, toc) — the parts, matching the page titles they introduce word for word
- headline (x1, stats) — the 2-4 numbers that ARE the period
- result (x2-5, chart / table / layout / stats) — one page per area, each with its own takeaway line
- driver (x1-2, compare / text / quote / chart) — WHY it moved — a report without causes is a dashboard
- risk (optional, bullets / table / compare) — what is off track, said plainly and early
- ahead (optional, timeline / bullets / layout) — next period, so the reader knows what changes
- close (x1, summary) — the same numbers as headline, now as conclusions
- decide — extract one decision. Audience: the decision maker. Success: an approval, or a named chosen option. Budget: ~8 slides.
- open (x1, cover) — put the DECISION in the title, not the topic
- question (x1, text / layout / bullets) — the question, the deadline, and who decides — one page
- context (optional, stats / chart / timeline) — what changed that makes this a choice now
- options (x1-2, compare / table / layout) — A next to B on ONE page — never A then B on two
- criteria (optional, table / layout / bullets) — how we will judge, agreed before the answer
- impact (x1, chart / table / stats) — the numbers per option — cost, risk, upside
- recommend (x1, text / quote / layout / stats) — our pick and the one reason — earned AFTER the comparison
- ask (x1, summary) — exactly what you want approved, and by when
- align — everyone holds the same picture. Audience: internal team or a new client. Success: each person can say what their part is. Budget: ~16 slides.
- open (x1, cover) — the thing we are all now inside of
- why (x1, text / quote / stats) — the goal in one line everyone can repeat
- map (optional, toc) — the parts, so nobody wonders what is coming
- picture (x1, layout / timeline / chart / image) — the WHOLE thing on one page — the page people photograph
- detail (optional, bullets / layout / table / chart) — what each part contains
- roles (x1, table / compare / layout) — who owns what, by name — the page this deck exists for
- when (x1, timeline) — dates and milestones, six steps max
- rules (optional, bullets / layout / table) — how we work: cadence, channels, escalation
- close (x1, summary) — first actions with owners — variant split + nextSteps
- analyze — draw conclusions from data. Audience: a strategist. Success: one implication that sticks. Budget: ~12 slides.
- open (x1, cover) — the question as the title, not the dataset name
- question (x1, text / quote / stats) — what we set out to learn, and why it matters
- method (optional, bullets / table / layout) — sources, period, caveats — credibility is cheap here
- finding (x2-5, chart / table / stats / layout) — ONE finding per page, each with a takeaway sentence
- pattern (x1, compare / layout / text / timeline) — what the findings say TOGETHER — the synthesis page
- implication (x1, quote / stats / text / layout) — so what, for us, starting when
- close (x1, summary) — the conclusions, ranked by confidence
- teach — make it reproducible. Audience: a learner. Success: they can do it themselves afterwards. Budget: ~16 slides.
- open (x1, cover) — the skill, phrased as something they will be able to do
- outcome (x1, bullets / stats / text) — "after this you can…" — 3 concrete abilities
- map (optional, toc) — the route through the material
- concept (x1, layout / text / image / compare) — the mental model, before any button-pressing
- steps (x1, timeline / layout) — the procedure as numbered steps, six max
- walkthrough (x1-3, image / table / layout / chart) — do it once on a real artefact, with the real screen
- pitfalls (optional, compare / bullets / table) — what goes wrong, and the tell for each
- practice (x1, bullets / layout / table) — their turn — a checklist they can run unaided
- close (x1, summary) — recap plus where to get the material — variant thanks
- Set payload.purpose to the chosen id. Optional slots may be dropped; required ones may not.
- ── STEP 2: OUTLINE ─────────────────────────────────────────────────────
- List every slide BEFORE building, as: `n. <kind> — <one-line content>`, following the purpose's page table (slots list allowed kinds in preference order; optional slots may be dropped, required ones may not).
- Slide budget: follow the purpose's ~N (align/teach run long, decide stays tight). One idea per slide — split rather than cram.
- If the deck uses toc, its `sections` must match the page titles they introduce, word-for-word and in order.
- ── STEP 3: PICK A KIND PER SLIDE (content decides, not habit) ──────────
- 2–4 headline numbers            → stats  (never a bullets slide of numbers)
- trend over time                 → chart  chartType 'line' or 'area'
- side-by-side quantities         → chart  chartType 'bar'
- share of a whole                → chart  chartType 'doughnut' or 'pie', with a one-line takeaway
- A vs B (channels, plans, befores/afters) → compare
- process, schedule, roadmap      → timeline  (6 steps max)
- one customer voice or one-line insight   → quote
- detail rows                     → table, 5 rows max on the slide — beyond that keep the top 5 and point to the XLSX
- a mix on one slide, or the deck is getting repetitive → layout (12-column grid, see below)
- everything else                 → bullets (6 max) or text (80 words max)
- ── LAYOUT: free composition when no fixed kind fits ────────────────────
- { kind:'layout', title?, blocks:[ { span?:1-12, break?, card?, align?, body } ] }
- Blocks flow left→right and wrap when the row fills. body is one of:
- heading | paragraph | bullets | stat | quote | chart | image | kv | icon | step | chips | funnel | spacer
- Recipes: two-column = two span-6 · stat row = three span-4 with card:true ·
- chart + side notes = span-8 chart + span-4 card ·
- funnel page = span-7 funnel + span-5 card bullets · icon row = three span-4 icon with card:true ·
- ring row = span-4 stat blocks with pct (share/completion numbers draw as progress rings).
- Use this to break up a deck that would otherwise be five bullet slides.
- ── PAGE TYPES: pick the shape before the words ─────────────────────────
- two-column      → layout span-7 + span-5 (text left, visual right)
- icon + text rows→ span-12 step blocks with `icon` instead of `number`
- 2x2 / 2x3 grid  → bullets 'cards', or span-4/span-6 layout blocks
- half-bleed image→ image variant 'bleed' (picture owns one side edge-to-edge)
- big stat callout→ stats, or span-4 stat blocks (pct for shares)
- comparison cols → compare · process flow → timeline
- ── AGENDA / OVERVIEW PAGE ──────────────────────────────────────────────
- Default to toc with { label, desc } sections — it gets a different face per
- deck automatically. Only hand-build the agenda as a layout step-stack
- (span-12 step per item) when it needs numbers/icons: a hand-built agenda
- looks the SAME in every deck.
- ── NO DIVIDER PAGES ────────────────────────────────────────────────────
- There is no divider kind in the schema. The part name belongs in the
- FOLLOWING page's title ("FUNNEL · What runs where"). Do not fake a divider
- with a text or cover slide carrying just a number and a heading.
- ── HOUSE DESIGN (enforced by the engine) ───────────────────────────────
- One motif: the CIRCLE — icons in tinted circles, circular number chips,
- corner-circle decoration. No accent stripes: no rule under a title, no bar
- down a slide edge, no full-width header/footer band.
- Sandwich: dark cover, light content, dark close (summary variant 'thanks').
- Slide titles render at 36pt — keep them to 8 words so they fit at that size.
- The tool also returns GEOMETRY notes (text overlap, ink off the slide,
- content inside the 0.3in edge gutter). Those are measured, not guessed —
- fix every one.
- ── VARIETY RULES (hard) ────────────────────────────────────────────────
- Never 3 consecutive slides of the same kind.
- Never 2 consecutive text-only slides (bullets / text count as text-only).
- A deck of 6+ slides must use at least 4 distinct kinds.
- Every 2-3 pages, one page carries a graphic device: chart, table, timeline
- (chevron = process strip), funnel, icons, or a pct stat ring.

### 2. Execute — Build with tool_write_pptx

- ── THEME: pick by topic domain ─────────────────────────────────────────
- twixy    (fallback) — Twixy brand purple; ONLY when no domain theme below fits. Do not default here out of habit — performance/analytics decks go to `charts`, social/agency audits to `vivid`.
- petrol   — calm teal on paper; editorial reports, monthly reviews
- navy     — deep navy + gold; finance, B2B, formal executive reporting
- vivid    — bold blue + orange; tech, startup, sports, launches, social/agency
- earth    — green + brown; food, nature, beauty, wellness, sustainability
- charts   — chart-optimized 5-color run; statistical / data-heavy reports
- night    — DARK deck (near-black + forest + gold); keynotes, premium, launches
- terra    — terracotta + sage; artisan, craft, food & beverage, heritage
- berry    — berry + cream; hospitality, beauty, lifestyle, premium retail
- slate    — neutral executive; carries a client brand hex without arguing
- Pass the preset name as payload.theme. Each theme carries its own font pairing — do not fight it.
- payload.brand — the client's hex ('#FF5A5F'): derives the WHOLE palette while the theme keeps fonts/shapes/dark. theme:'night' + brand = dark branded deck. Set it whenever the client's brand colour is known; contrast is auto-checked. payload.accent is a single-colour legacy override applied last.
- 🚨 These 10 are the ONLY valid names — an unknown theme is a hard error, not a silent fallback.
- ── STYLE: shape & whitespace personality (payload.style) ───────────────
- sharp   — right angles, tight spacing; finance, data-dense, formal reports
- soft    — slight rounding, moderate air; general corporate (safe default)
- rounded — big corners, generous whitespace; product marketing, friendly
- pill    — full pills, airy; brand showcases, launch events, premium
- Omit payload.style to use the theme's own default. Never mix — one style per deck.
- ── LAYOUT VARIANTS: vary the deck's face, keep dividers consistent ─────
- cover:    variant 'block' (color block) | 'split' (text + side panel) | 'center'
- toc:      'list' | 'sidebar' (accent bars) | 'cards'
- section:  'number' (ghost number) | 'accentBlock' | 'split'
- stats:    'cards' | 'bare' (huge numbers, no cards — pairs well with sharp)
- summary:  'takeaways' | 'split' (takeaways + Next Steps card, needs nextSteps) | 'thanks' (closing + contact)
- chart:    'full' | 'split' (chart left + takeaway side card, needs takeaway) | 'banner' (24pt takeaway ABOVE the chart)
- bullets:  'rows' (accent dots) | 'cards' (numbered tiles, ≤6) | 'numbered' (editorial numerals + hairlines) | 'twoCol' (≥4)
- compare:  'cards' | 'vs' (bare columns, center rail + VS chip) | 'stacked' (before/after bands, ≤3 bullets a side)
- table:    'grid' | 'zebra' (borderless striped) | 'kv' (2-col key/value without a grid)
- timeline: 'rail' (horizontal) | 'vertical' (best when steps carry desc text) | 'bars' (stage blocks + ghost numerals) | 'chevron' (arrow chain — the consulting process strip)
- text:     'rail' | 'panel' (title left, body card right) | 'twoCol'
- A variant that cannot hold the content falls back to the default and never drops text.
- 🚨 Two slides of the same kind in a row? Give them DIFFERENT variants. ALL section slides in one deck MUST use the SAME variant (dividers are a rhythm, not a variety show).
- ── PICTURES THE USER ATTACHED ──────────────────────────────────────────
- A dragged/pasted photo reaches you as a path in the user's message ('data/raw/…png'). That path is the only way a picture gets on a slide: use it as `imagePath` on an `image` slide, or in a layout block { type:'image', imagePath, caption? }.
- Three image faces: 'full' (framed under the title, safe default) · 'bleed' (half-bleed — photo owns one side, words the other) · 'hero' (the photo IS the page; title+caption on a plate over its foot — for the one picture that carries a slide; title renders at 40pt so keep it short).
- 🚨 Copy the path EXACTLY. Never invent a path, never use a web URL, never reference a file the user did not attach — the write fails with 'image not found' and names your path.
- 🚨 You cannot see the picture. Never describe its contents; caption it from what the user said, or omit the caption.
- In a `layout` grid a photo FILLS its cell — pick the span you want it to occupy. 2+ pictures in one row become a matched gallery strip; a lone picture keeps its own shape.
- ── TEXT BUDGETS (overflow is the #1 quality killer) ────────────────────
- bullets: 6 per slide max, 12 words per bullet max. Body text: 80 words max. Slide titles: 8 words max.
- stats: 2–4 items, value short ('+34%', '2.8x'), label 2–4 words.
- chart takeaway / summary closing: exactly one line.
- 🚨 NO em dash ('—') or en dash ('–') in slide text. A plain hyphen in a term or range ('A-B', '2024-2025') is fine. Use a comma, a colon or a second sentence instead. The renderer strips long dashes before they reach the slide, so a sentence built around one reads wrong.
- Numbers speak, adjectives don't — 'Conversion 12.4%' beats 'conversion grew significantly'.
- ── SPEAKER NOTES (mandatory) ───────────────────────────────────────────
- Every slide gets `notes`: 1–2 sentences of what the presenter says on this slide. Notes carry the reasoning; the slide carries the conclusion.
- ── STARTING FROM AN EXISTING DECK — two paths, ask which ───────────────
- KEEP their design (fix wording, notes, duplicate/delete/reorder slides, fill a .potx): tool_edit_pptx. The original masters/theme/media survive byte-for-byte. Read the returned `outline` to confirm the edit.
- REDESIGN in our system (re-theme, restructure): tool_read_pptx FIRST — it returns the outline plus `payload`, the same shape tool_write_pptx takes. It recovers CONTENT, not layout: charts come back as bullets (their data lives in an embedded workbook), so re-pick kinds using the table above.
- When the user just says "fix this deck" without specifying, small text fixes = edit; anything about looks/theme/structure = redesign.
- ── OUTPUT PATH ─────────────────────────────────────────────────────────
- Write to data/reports/<short-slug>.pptx. Never prefix with `twixy/`.
- ── SCHEMA: use these field names exactly (generated — do not hand-edit) ─
- cover    { kind, title, subtitle?, date?, badge?, kicker?, chips?: string[],
- variant?: block|split|center }
- toc      { kind, sections: (string or { label, desc? })[], title?,
- variant?: list|sidebar|cards }
- stats    { kind, items: [{ value, label, sublabel? }], title?, variant?: cards|bare }
- compare  { kind, left: { title, bullets: string[] },
- right: { title, bullets: string[] }, title?, variant?: cards|vs|stacked }
- quote    { kind, text, attribution? }
- timeline { kind, steps: [{ label, desc? }], title?,
- variant?: rail|vertical|bars|chevron }
- chart    { kind, chartType: bar|line|pie|doughnut|area, categories: string[],
- series: [{ name, values: number[] }], title?, takeaway?, source?,
- variant?: full|split|banner }
- summary  { kind, takeaways: string[], title?, closing?, nextSteps?: string[],
- contact?, variant?: takeaways|split|thanks }
- bullets  { kind, bullets: string[], title?, variant?: rows|cards|numbered|twoCol }
- text     { kind, body, title?, variant?: rail|panel|twoCol }
- image    { kind, imagePath, title?, caption?, variant?: full|bleed|hero }
- table    { kind, headers: string[], rows: (string|number|null)[][], title?,
- variant?: grid|zebra|kv }
- layout   { kind,
- blocks: [{ span?: 1-12, break?, card?, align?: top|middle, minH?, body }],
- title? }
- 🚨 Valid kinds are ONLY: cover, toc, stats, compare, quote, timeline, chart, summary, bullets, text, image, table, layout. An unknown kind or field name is a hard error — the deck does not render.
- ── LITERAL CALL SHAPE (copy, then adapt — one slide per line) ──────────

- { "kind": "chart", "title": "Monthly revenue", "chartType": "line", "categories": ["Jan", "Feb", "Mar"], "series": [ { "name": "2026", "values": [120, 135, 160] } ], "takeaway": "The gap widened after the April campaign.", "notes": "Point at the inflection." },
- { "kind": "summary", "takeaways": ["Keep the short-form format", "Reinforce the lower funnel"], "closing": "H2 target: revenue +40%", "notes": "Close with the ask." }

- 🚨 Field names and valid kinds are in the SCHEMA block above — a slide with an invented kind or field does not render.

### 3. Track Results — QA pass — Content / Design / Coherence

- Run all three checks on the payload BEFORE the final write; after a failed check, fix the payload and call tool_write_pptx again with the SAME relPath (overwrite). One rewrite round is normal, not exceptional.
- ── CONTENT ─────────────────────────────────────────────────────────────
- Zero placeholders: no lorem, XX, TBD, 'N/A', 'sample', empty strings.
- Every number on a slide traces to collected input data. A number you cannot source gets cut or explicitly marked as an estimate.
- Write slides in the LANGUAGE OF THE USER'S REQUEST and source data — do not switch languages on your own.
- ── DESIGN ──────────────────────────────────────────────────────────────
- Count the kinds actually used: 6+ slides ⇒ at least 4 distinct kinds, no 3-in-a-row repeats, no consecutive bullets/text slides. If violated, convert the weakest text slide into stats / chart / compare using its own content.
- ── COHERENCE ───────────────────────────────────────────────────────────
- toc sections == section slide titles, same wording, same order. Slide order matches the ANALYZE outline. The summary's takeaways answer the promise the cover made.
- Skeleton present: 6+ slides ⇒ toc + ≥1 section + final summary all exist. Any missing ⇒ FAIL — restructure and rewrite, do not ship a cover-then-data-dump deck.
- ── READ THE TOOL'S REPLY — TEXT AND IMAGE ──────────────────────────────
- tool_write_pptx returns `warnings` (content clamped / table rows cut / text overflowing / font shrunk), `structure` (missing toc·section·summary, same kind 3 in a row, text-only runs), and an IMAGE: a numbered contact sheet of every slide as rendered.
- LOOK at the sheet. Check: text overflowing its box · elements overlapping · unreadable contrast (especially on the night theme) · inconsistent margins · three consecutive slides that look the same.
- If the image or the text feedback shows a problem, FIX the payload and call tool_write_pptx again with the SAME relPath (overwrite). ONE fix round max — do not loop. Never report success over a non-empty warning list.
- Report when done: relPath, slide count, kinds used, theme name. If every slide came out 'bullets', the outline step was skipped — redo ANALYZE.
